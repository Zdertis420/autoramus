# Phase 1. Как убедиться, что работает

Все команды — из каталога `ramusc/`.

## До начала

```bash
make check
go run ./cmd/ramusc ../examples/skirt.yaml -o /tmp/skirt.rsf; echo "код: $?"
```

Сегодня второе даёт код 2 и отказ «у работ нет координат». Это и есть дефект,
который чинится.

## Слепок «как было»

```bash
go run ./cmd/ramusc decompile ../examples/ИзготовлениеЮбки.rsf -o /tmp/yubka.yaml
go run ./cmd/ramusc /tmp/yubka.yaml -o /tmp/before.rsf
```

Документ с полной геометрией. После фичи он обязан давать файл, совпадающий с
`/tmp/before.rsf` побайтово: раскладке там делать нечего.

## Сценарий 1 — совпадение с Ramus (US2, FR-002)

```bash
go test ./internal/layout -run TestMatchesRamus -v
```

Ожидается: четыре блока получают ровно те координаты, что лежат в `тест.rsf`, —
`(80, 80)`, `(273⅓, 160⅔)`, `(466⅔, 241⅓)`, `(660, 322)`, размер `72 × 50.4`.
Это единственное место, где сверка идёт с числами, а не со свойствами: эталон
есть только для четырёх блоков.

## Сценарий 2 — свойства при любом числе блоков (FR-003)

```bash
go test ./internal/layout -run TestFitsAndDoesNotOverlap -v
```

Ожидается: для числа работ от одной до двадцати пяти блоки не накладываются и не
выходят за лист. С двадцати шести проверка не предъявляется — граница названа в
FR-003.

## Сценарий 3 — образцовый документ компилируется (US1, SC-001)

```bash
rm -f /tmp/skirt.rsf
go run ./cmd/ramusc ../examples/skirt.yaml -o /tmp/skirt.rsf; echo "код: $?"
go run ./cmd/ramusc dump /tmp/skirt.rsf | sed -n '/^РАБОТЫ/,/^ПОТОКИ/p'
```

Ожидается: код 0, файл создан, четыре работы. Геометрия подработ — по таблице из
[contracts/layout.md](./contracts/layout.md); корневая в центре листа.

## Сценарий 4 — ручное сильнее вычисленного (US3, FR-007)

```bash
go run ./cmd/ramusc /tmp/yubka.yaml -o /tmp/after.rsf
cmp /tmp/before.rsf /tmp/after.rsf && echo "не изменилось — верно"
```

Файлы обязаны совпасть побайтово. Расхождение означает, что раскладка полезла
туда, где всё задано.

```bash
go test ./internal/layout -run TestOverride -v
```

Ожидается: при частично заданной геометрии сдвигается ровно то, что задано, а
остальное берётся из раскладки.

## Сценарий 5 — порядок следует связям (FR-005)

```bash
go test ./internal/layout -run TestOrder -v
```

Ожидается: на `skirt.yaml` порядок совпадает с объявленным (там он и есть
топологический); при перестановке объявлений с теми же связями порядок блоков не
меняется; модель с обратной связью раскладывается и не зацикливается.

## Сценарий 6 — детерминированность (FR-008, SC-005)

```bash
go run ./cmd/ramusc ../examples/skirt.yaml -o /tmp/a.rsf
go run ./cmd/ramusc ../examples/skirt.yaml -o /tmp/b.rsf
cmp /tmp/a.rsf /tmp/b.rsf && echo "побайтово одинаковы — верно"
```

## Сценарий 7 — проверка человеком

Не автоматизируется.

1. Открыть `/tmp/skirt.rsf` в Ramus.
2. Убедиться: три подработы стоят по диагонали слева-сверху вниз-вправо, как в
   любой модели IDEF0; блоки не наезжают, все на листе.
3. Открыть контекстную диаграмму A-0: единственный блок в центре листа.
4. Стрелок нет — так и должно быть на этой ступени.

Если картинка выглядит инородно рядом с `тест.rsf`, открытым в соседнем окне, —
значит формула воспроизведена неверно, и ни один автоматический тест этого не
покажет.
