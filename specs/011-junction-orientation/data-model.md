# Data Model: ход конца в узле

**Фича**: 011-junction-orientation

Новых сущностей не появляется ни в IR, ни в схеме входного языка, ни в наборе
таблиц `.rsf`. Меняется **значение одной колонки** в уже существующих строках и
**форма ветвления**, которая возвращается к прежней.

## Ход конца

Направление, в котором сегмент уходит из точки. Пишется в колонку `POINT_TYPE`
таблицы `attribute_sector_points`.

| Значение | Смысл |
|---|---|
| `0` | сегмент уходит из точки по горизонтали |
| `1` | сегмент уходит из точки по вертикали |
| `-1` | ход не определён |

Определяется **только** у первой и последней точки ломаной, и только если
соответствующий конец сегмента сидит на узле. Считается по соседней точке:
у первой — по второй, у последней — по предпоследней.

## Кто получает ход, а кто нет

Признак наблюдаемый и в наших данных уже выражен — видом конца сегмента.

| Конец | Вид в IR | Номер кросспоинта | Ход |
|---|---|---|---|
| Узел ветвления | `EndpointNode` | из счётчика узлов | **`0` или `1`** |
| Прицеплен к работе | `EndpointFunction` | из сшивки уровней | `-1` |
| На краю листа | `EndpointBorder` | из сшивки уровней | `-1` |
| Точка внутри ломаной | — | нет | `-1` |

Существенно, что номер кросспоинта есть и у сшивки уровней: различать концы по
наличию номера **нельзя**, иначе под правило попадут 140 концов на «чахохбили»,
у которых Ramus ставит `-1`. Различать нужно по виду конца.

## Вырожденный случай

Ход не определён и пишется `-1`, если соседнего отрезка нет (ломаная из одной
точки) либо он вырожден — нулевой длины или идёт наискось. Сказать
«горизонталь» про отрезок без направления значило бы соврать в поле, по
которому Ramus рисует.

## Дерево ветвления (возврат)

Форма возвращается к той, что была до фичи 010, и описана она там же, где была:

| Часть | Что это | Сколько |
|---|---|---|
| Вход | от края листа до первого узла | 1 сегмент |
| Магистраль | цепочка узлов вдоль общей линии, параллельной краю | `n−2` |
| Отводы | из каждого узла в свою работу | `n−1` |
| Дотяжка | у последнего узла — второй потребитель | входит в отводы |

Итого `2n−1` сегментов. Общая линия — одна на поток, а не полоса на каждую
ветку.

## Инварианты

| Инвариант | Требование |
|---|---|
| У каждого конца-узла ход записан | FR-001 |
| Записанный ход совпадает с фактическим направлением | FR-002 |
| У прочих концов и точек ход `-1` | FR-003, FR-004 |
| Край листа пересекается один раз, узел — одна точка | FR-007 |
| Сегменты разных стрелок не накладываются | FR-008 |
| Две сборки дают побайтово равные файлы | FR-010 |

## Что НЕ является сущностью этой фичи

**Поле языка.** `POINT_TYPE` не переносится из документа и не выводится
декомпилятором: оно **вычисляется** из геометрии и вида конца — так же, как
признак туннеля (Р19). В круге «документ → файл → документ» его нет и быть не
должно.
