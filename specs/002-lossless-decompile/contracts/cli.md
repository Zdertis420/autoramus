# Phase 1. Контракт командной строки

Только то, что меняет эта работа. Остальное описано в `CLAUDE.md` и контракте
фичи `001`.

## Что меняется

| Команда | Меняется |
|---|---|
| `ramusc decompile <file.rsf>` | в выводе появляются секции люка; появляется предупреждение о потерях |
| `ramusc validate <file>` | принимает люк в новых местах документа |
| `ramusc dump <file.rsf>` | не меняется |

## `decompile`: коды возврата

| Код | Когда | Поток вывода | Поток ошибок |
|---|---|---|---|
| 0 | файл перенесён | документ | пусто |
| 0 | часть содержимого не перенесена | **документ печатается полностью** | перечень потерь |
| 2 | содержимое не выражается языком по существу | пусто | перечень находок |
| 2 | файл не читается, неверный вызов | пусто | причина |

**Два канала, и их нельзя путать.** Код 2 остаётся за тем, что языком не
описывается вовсе: работа без имени не имеет идентификатора, документ про неё не
написать. Потеря оформления — другое: модель перенесена, работать с ней можно,
блокировать нечего.

Кода 1 у `decompile` по-прежнему нет.

## `decompile`: предупреждение о потерях

Идёт в поток ошибок всегда. Строится из перечня, а не собирается по случаю:
FR-005 требует свернуть повторы в одну запись с количеством.

```
Модель.rsf: перенесено не всё
  подписи стрелок (F_SECTOR_PROPERTIES): 103
  определение модели (F_PROJECT_PREFERENCES: DEFINITION, MODEL_LETTER): 1
```

В выводе YAML тот же перечень повторяется комментарием в шапке — рядом с уже
существующим предупреждением про потоки без стрелок:

```yaml
# Декомпилировано из Модель.rsf.
# Перенесено не всё (2 вида):
#   подписи стрелок (F_SECTOR_PROPERTIES): 103
#   определение модели (F_PROJECT_PREFERENCES): 1
model: Формирование ТП
```

Причина дублирования: вывод часто уходит в файл по `-o`, и тогда поток ошибок
пролетает мимо глаз, а узнать о потере автор должен при работе с результатом.

В выводе JSON комментариев нет (Р10) — там перечень остаётся только в потоке
ошибок.

**Пустой перечень ничего не печатает.** Ни в шапку, ни в поток ошибок.

## Люк в выводе

Печатается у элемента после его собственных полей. Отсутствует целиком, если
класть нечего.

```yaml
functions:
  - name: Разработка структуры программы
    in:        [Исходные данные]
    raw:
      - attribute: F_BACKGROUND
        value: -1
      - attribute: F_STATUS
        value: 0

layout:
  arrows:
    - flow: Исходные данные
      segments:
        - on: Формирование ТП
          points: [[7, 349], [37, 349]]
          raw:
            - attribute: F_SECTOR_PROPERTIES
              value: {SHOW_TEXT: 1, TEXT_X: 391.25, TEXT_Y: 22.0}
```

Порядок записей — по имени атрибута; порядок колонок внутри значения — как в
таблице. Две декомпиляции одного файла дают одинаковые байты.

## Обратная совместимость

**Документы, написанные людьми, не ломаются.** Люк во всех новых местах
необязателен: модель без единого люка остаётся валидной.

**Эталоны трёх моделей изменятся** — в них появятся секции люка. Это осознанное
изменение поведения, а не регрессия: переписывается отдельным шагом и отдельным
коммитом, чтобы дифф читался.

**Не меняется**: побайтовый round-trip `.rsf`, отказ по непереносимому
содержимому и его три вида, коды диагностики валидатора.
