# Quickstart: проверка формы дерева

Как убедиться, что ветки несут свои повороты, и как воспроизвести измерения, на
которых построен план.

## Предварительно

```bash
cd ramusc && make build     # даст ./ramusc/ramusc
```

Внешнего ничего не нужно. Ramus для проверки **не требуется**: положение
поворота выражается координатами и меряется по собранному файлу. Само скругление
рисует Ramus, и его смотрит человек — но только после того, как числа сошлись.

## 1. Посчитать повороты в любом файле

```bash
./ramusc/ramusc examples/chakhokhbili.yaml -o /tmp/m.rsf
python3 specs/010-arrow-corner-joins/evidence/turns.py /tmp/m.rsf
```

Печатает два числа: сколько поворотов лежит внутри ломаных (Ramus их скругляет)
и сколько приходится на стыки секторов (скругления не будет).

Скрипт читает `.rsf` напрямую, мимо нашей раскладки, и потому ловит расхождение
между тем, что раскладка думает, и тем, что доехало до файла. Тот же приём, что
у `dump` против `algodemo/rsf.py`.

**Ожидаемо до фичи**: внутри 23, на стыке 22.
**Ожидаемо после**: внутри 38, на стыке 22.

Повороты на стыке никуда не денутся, и это правильно: они приходятся на
ответвления, где линия и должна расходиться под прямым углом. У самого Ramus их
4–17 на файл.

## 2. Сравнить с образцом

```bash
python3 specs/010-arrow-corner-joins/evidence/turns.py \
    examples/ИзготовлениеЮбки.rsf examples/тест.rsf examples/ФормированиеТП.rsf
```

Три файла, собранные самим Ramus: 8/4, 11/7 и 34/17.

Долю между моделями сравнивать нельзя — она зависит от того, сколько в модели
ветвлений против простых связей. Смотреть надо на структуру (пункт 3), а доля
нужна лишь чтобы «стало лучше» имело число.

## 3. Посмотреть на геометрию, не открывая Ramus

```bash
./ramusc/ramusc decompile /tmp/m.rsf --json > /tmp/m.json
python3 specs/010-arrow-corner-joins/evidence/draw.py \
    /tmp/m.json "Приготовление чахохбили" /tmp/m.png
```

Рисует блоки и ломаные в PNG, точки помечает красным. Скругления не рисует —
и не должен: смысл в том, чтобы увидеть, где стоят точки. Ветка, у которой своя
точка поворота есть, видна сразу; голый отвод — тоже.

Этим же скриптом снят образец: `evidence/draw.py` на декомпиляции
`ИзготовлениеЮбки.rsf` даёт картинку, совпадающую с той, что автор показал как
правильную.

## 4. Тесты

```bash
cd ramusc && make check      # форматирование, go vet, все тесты
go test ./internal/layout/   # только раскладка
```

Проверки, добавленные фичей:

| Тест | Что требует |
|---|---|
| `TestBranchCarriesItsOwnCorner` | у каждой ветки свой поворот; голых отводов нет |
| `TestTurnsAreInsidePolylines` | счёт поворотов сходится с `evidence/turns.py` |

Проверки, которые обязаны остаться зелёными: `TestTreeShape`,
`TestTreeNodesAreOnePoint`, `TestNoNodesWithoutBranching`,
`TestTreeIsDeterministic`, `TestNoSegmentOverlap`, `TestGeometryIsLawful`,
`override_test.go`.

**Порядок работ обратный обычному**: `TestBranchCarriesItsOwnCorner` пишется
первым и обязан покраснеть на 22 ветках — до того, как тронут построение дерева.

## 5. Убедиться, что ничего не сломалось

```bash
cd ramusc && go test ./...
git diff --stat ramusc/testdata/golden/     # обязано быть пусто
```

Эталоны сняты с файла самого Ramus, форма нашего дерева их не касается.

## 6. Глазами

```bash
./ramusc/ramusc examples/chakhokhbili.yaml -o examples/chakhokhbili.rsf
```

Открыть в Ramus. Каждая ветка механизма обязана заворачивать в свою работу
скруглённым уголком — так же, как в `examples/ИзготовлениеЮбки.rsf`. Эта
проверка единственная смотрит на то, ради чего фича затевалась, и
автоматической она не станет: скругление рисует внешняя программа с GUI.
