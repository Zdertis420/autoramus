# Контракт: инвариант кросспоинтов и раздел `dump`

## 1. `internal/rsf` — новая функция

```go
// Tunnel — конец сектора, который Ramus нарисует в скобках.
type Tunnel struct {
    Sector     int64  // элемент сектора
    Start      bool   // начало сектора, а не конец
    Crosspoint int64  // номер узла, у которого не хватает половины
    Diagram    int64  // на чьей диаграмме нарисован сегмент
    Stream     int64  // какой поток несёт
    Ins, Outs  int    // наполнение узла: ради него всё и считается
}

// Tunnels отдаёт концы секторов, которые Ramus нарисует туннельными.
//
// Правило снято с исходников Ramus, а не с поля TUNNEL_SOFT: скобки рисуются
// там, где у кросспоинта нет входов либо нет выходов.
func (m *Model) Tunnels() []Tunnel
```

Подписи существующих функций `internal/rsf` не меняются.

## 2. Правило

Конец сектора туннельный, когда у его кросспоинта пуст `ins` либо пуст `outs`, и
**не** выполнено ни одно из двух:

1. конец лежит на краю листа **контекстной** диаграммы A-0 (владелец диаграммы
   принадлежит квалификатору `F_BASE_FUNCTIONS`);
2. конец прицеплен к блоку, у которого нет ни одного потомка.

Наполнение узла считается по `attribute_sector_borders`: начало сектора
(`F_SECTOR_BORDER_START`) даёт `outs`, конец (`F_SECTOR_BORDER_END`) — `ins`.

Происхождение правила и цитаты из Ramus — `research.md`, В1. Исполняемая
запись, пригодная для сверки, — `evidence/tunnels.py`.

## 3. Инвариант, который держит компилятор

> На документе, где ни одна работа не назвала поток в `tunnel`, `Tunnels()`
> собранного файла пуст.

Проверяется таблицей: по каждому документу `testdata/documents/` и по
`examples/skirt.yaml`, `examples/skirt-full.yaml`. Новый документ добавляется в
перечень, код теста при этом не трогается.

Отдельно — сверка с реальностью, она же защита от неверно выведенного правила:

| Файл `internal/fixtures` | Ожидаемое число туннелей |
|---|---|
| `тест.rsf` | 0 |
| `ИзготовлениеЮбки.rsf` | 0 |
| `ФормированиеТП.rsf` | 1 |
| `testModel.rsf` | 0 |

Ноль на файлах, записанных самим Ramus, — не украшение, а единственное
доказательство того, что правило выведено верно.

## 4. `ramusc dump` — новый раздел

Печатается **последним**, после `ICOM ПО РАБОТАМ`. Первые три раздела
(`РАБОТЫ`, `ПОТОКИ`, `СЕКТОРЫ`) повторяют вывод `algodemo/rsf.py` слово в слово,
и трогать их нельзя — на этом держится сверка диффом.

```
ТУННЕЛИ (концы в скобках)
    56  конец    узел#41  вход=1 выход=0  поток='Заявка'            диаграмма='Изготовление юбки'
    58  начало   узел#44  вход=0 выход=1  поток='Заявка в работе'   диаграмма='Изготовление юбки'
```

Когда туннелей нет, раздел печатается с одной строкой `туннелей нет` — так же,
как прочие разделы не исчезают на пустой модели.

Эталоны `dump` на `examples/ИзготовлениеЮбки.rsf` переписываются `make golden`;
диффом должно быть видно ровно добавление раздела с `туннелей нет`.

## 5. Чего функция не делает

Она **не судит**, правилен туннель или нет: скобки у DFD-декомпозиции с явным
`tunnel` — такой же результат, как скобки у потерянной стрелки. Отличить их можно
только по документу, и это работа валидатора, а не разбора файла.

Она **не смотрит** на `TUNNEL_SOFT`. Поле остаётся нулём (`research.md`, В2), и
на результат не влияет.
