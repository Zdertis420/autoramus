# Phase 1. Контракт CLI

Меняется одна ветка — компиляция, `ramusc <файл>`. `validate`, `dump`,
`decompile`, `version` и `help` не затрагиваются.

---

## `ramusc <файл> [-o вывод.rsf]`

### Было

Проверка проходила до конца, после чего команда честно сообщала, что генератора
нет, и возвращала 2. Файл не создавался никогда.

### Стало

| Условие | Файл | stdout | stderr | Код |
|---|---|---|---|---|
| Документ валиден, координаты есть, потоков нет | создан | пусто | пусто | 0 |
| Документ валиден, координаты есть, потоки объявлены | создан | пусто | предупреждение о ненаписанных связях | 0 |
| Документ валиден, есть предупреждения проверки | создан | пусто | предупреждения | 0 |
| Документ невалиден | **не создан** | пусто | диагностика, как у `validate` | 1 |
| У работы нет координат | **не создан** | пусто | отказ: автораскладки пока нет | 2 |
| Заготовка испорчена или недоступна | **не создан** | пусто | внутренняя ошибка со ссылкой на баг-трекер | 2 |
| Неверный вызов, файл не читается | **не создан** | пусто | сообщение об ошибке | 2 |

Коды остаются теми же, что и во всём остальном инструменте: 0 — успех, 1 — вход
невиноват программе, а виноват автору, 2 — виновата программа или вызов.

### Куда пишется файл

* `-o вывод.rsf` — явный путь;
* без `-o` — рядом с входным, с расширением `.rsf`: `model.json` → `model.rsf`;
* `-o -` — стандартный вывод. `.rsf` бинарен, и мешать его с диагностикой
  нельзя: при `-o -` вся диагностика уходит в поток ошибок.

Файл создаётся **только** после того, как весь ZIP собран в память. Наполовину
записанного `.rsf` не остаётся ни при какой ошибке.

### Предупреждение о ненаписанных связях

Печатается всякий раз, когда в документе объявлены потоки, — то есть почти
всегда, потому что секция `flows` обязательна (Р6).

```
<файл>: связи в .rsf пока не записываются
  объявлено потоков: 14
  в файле будут только блоки работ; стрелки появятся следующей версией
```

Это сообщение о состоянии программы, а не об ошибке в документе. Поэтому:
код возврата 0, в `--json` оно не попадает и объектом диагностики не является.

### Отказ при отсутствии координат

```
<файл>: у работ нет координат, а автораскладки пока нет
  без координат: «Раскроить ткань», «Сшить детали»
  добавьте секцию layout или дождитесь автораскладки
ничего не записано
```

Код 2, файла нет. Это не ошибка автора — язык позволяет опустить `layout` (Р2),
— а состояние программы, и поэтому исход тот же, что у отказа декомпилятора.

## Что остаётся прежним

* **Одна диагностика на один смысл.** Компиляция начинается с той же проверки,
  что `validate`, и печатает те же объекты. Второго набора сообщений не
  появляется.
* **`--json`.** Для компиляции означает то же, что для `validate`: машинный
  вывод диагностики. Формат файла на выходе он не меняет.
* **Паника ловится** и превращается в код 2 со стеком и ссылкой на баг-трекер.

## Ожидаемое поведение на примерах

### `examples/skirt.yaml`

Документ без секции `layout` — координат нет. Ожидается отказ с кодом 2 и
перечнем работ без координат.

### Документ, полученный декомпиляцией `examples/ИзготовлениеЮбки.rsf`

Координаты есть у всех работ. Ожидается файл с кодом 0 и предупреждением о
ненаписанных связях: потоков в нём четырнадцать.

Собранный файл обязан открываться `ramusc dump` и показывать то же дерево работ
и ту же геометрию, что исходный `ИзготовлениеЮбки.rsf`. Побайтового совпадения с
ним не ожидается и не требуется: идентификаторы элементов назначает компилятор.

### Тот же документ, скомпилированный дважды

Два файла обязаны совпадать побайтово.
