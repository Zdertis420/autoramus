# Контракт: ход конца в узле

## 1. Внешние интерфейсы не меняются

| Поверхность | Изменение |
|---|---|
| CLI `ramusc`: команды, флаги, коды возврата | нет |
| `--json` диагностики, коды `internal/diag` | нет |
| Входной язык, `model.schema.json` | нет |
| IR (`internal/ir`) | нет |
| Таблицы, колонки и последовательности `.rsf` | нет |
| `layout.Apply(m *ir.Model)` | подпись та же |

Меняется **значение** колонки `POINT_TYPE` в строках `attribute_sector_points` и
**геометрия** ветвящихся стрелок (возврат к форме магистрали). Число строк,
секторов, точек и связей не меняется.

Новых диагностик нет: ход конца — не свойство входа, сообщать пользователю
нечего.

## 2. Правило записи

```go
// pointTypeOf отдаёт ход конца: 0 — сегмент уходит горизонталью, 1 —
// вертикалью, -1 — ход не определён.
//
// Заполняется только у концов, сидящих на узле. У концов, прицепленных к
// работе, у краёв листа и у точек внутри ломаной Ramus всегда пишет -1 —
// измерено на трёх его файлах без исключений.
func pointTypeOf(s *ir.Segment, i int) string
```

Таблица решения:

| Точка | Конец | Соседний отрезок | Результат |
|---|---|---|---|
| первая | `EndpointNode` | горизонтален | `0` |
| первая | `EndpointNode` | вертикален | `1` |
| последняя | `EndpointNode` | горизонтален | `0` |
| последняя | `EndpointNode` | вертикален | `1` |
| первая/последняя | не узел | любой | `-1` |
| внутри ломаной | — | — | `-1` |
| любая | узел | вырожден или наискось | `-1` |

Константа `pointType = "-1"` в `internal/generate/sector.go` перестаёт быть
единственным источником значения; комментарий при ней («правила для 0 и 1 из
данных не видно») устарел и заменяется мерой.

## 3. Инвариант, который проверяется тестом

```go
// TestJunctionEndsCarryOrientation — у каждого конца-узла записан ход.
//
// Проверяется по собранному .rsf, а не по раскладке: поле пишет генератор, и
// проверять надо то, что доехало до файла.
func TestJunctionEndsCarryOrientation(t *testing.T)
```

Правила проверки:

1. Конец считается узловым, если в `attribute_sector_borders` у него есть номер
   кросспоинта, а `FUNCTION` и `BORDER_TYPE` пусты (`-1`).
2. У такого конца `POINT_TYPE` обязан быть `0` или `1`.
3. Значение обязано совпадать с фактическим направлением отрезка, считая по
   соседней точке.
4. У всех прочих точек `POINT_TYPE` обязан остаться `-1` — в том числе у концов
   со сшивкой уровней, которых на «чахохбили» 140.

Проверка идёт по набору документов; новый документ добавляется в перечень, код
теста не трогается.

## 4. Что обязано уцелеть

| Инвариант | Где сторожится |
|---|---|
| Узел — одна точка | `TestCrosspointIsOnePoint`, `TestTreeNodesAreOnePoint` |
| Форма дерева `2n−1`, вход один | `TestTreeShape` |
| Без ветвления узлов нет | `TestNoNodesWithoutBranching` |
| Сегменты разных стрелок не накладываются | `TestNoSegmentOverlap` |
| Стрелка не идёт сквозь блок и не наискось | `TestGeometryIsLawful` |
| Точки одной прямой в секторе делят ординату | `TestOrdinatesSharedWithinSector` |
| Каждая связь нарисована | `TestEveryLinkDrawn` |
| Авторская геометрия не тронута | `override_test.go` |
| Круг «документ → файл → документ» замкнут | `generate`, `decompile` |
| Две сборки дают побайтово равные файлы | принцип III |

## 5. Тесты, которые уходят вместе с откатом

`TestBranchCarriesItsOwnCorner` и помощник `spineOf` требуют формы хребта и
удаляются вместе с ней. Это не потеря покрытия: инвариант, который они
сторожили, был свойством отменённой формы.

`TestTurnsAreInsidePolylines`, `TestSimpleArrowsKeepTurnsInside` и
`TestStraightBorderArrowStaysOneSegment` к форме ветвления не привязаны и
остаются.

## 6. Эталоны

`testdata/golden/` сняты с `examples/ИзготовлениеЮбки.rsf` — файла, который мы
только читаем. `dump` печатает прочитанное, а не записанное, и ни ход конца, ни
форма дерева на эталоны не влияют. `make golden` этой фиче не нужен.
