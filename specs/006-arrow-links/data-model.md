# Модель данных: стрелки от связи до строки таблицы

Сущности берутся из уже существующего IR — новых типов не заводится. Ниже —
что именно кладётся в существующие поля и по каким правилам.

## 1. Что есть уже

| Тип IR | Роль в этой фиче |
|---|---|
| `ir.Model.Flows` | словарь имён потоков; задаёт порядок записи `F_STREAMS` |
| `ir.Model.Links` | связи обеих форм, ICOM и `links`, уже сведённые в одно (Р7) |
| `ir.Layout.Functions` | геометрия блоков; к этой фиче приходит заполненной |
| `ir.Layout.Arrows` | **заполняется этой фичей**: по элементу на стрелку |
| `ir.ArrowLayout` | стрелка: имя потока и её сегменты |
| `ir.Segment` | сегмент на одной диаграмме: `On`, `Context`, `From`, `To`, `Points` |
| `ir.Endpoint` | конец: блок со стороной, край листа или узел |
| `ir.Point` | точка ломаной |

Представление уже проверено с другой стороны: декомпилятор складывает в него
стрелки из настоящих файлов. Генератору достаточно прочесть то же самое.

## 2. Диаграмма

Единица рисования — та же, что и у раскладки блоков.

| Диаграмма | Владелец сегментов (`Segment.On`) | `Segment.Context` |
|---|---|---|
| A-0, контекстная | имя модели | `true` |
| A0 и ниже | имя работы-родителя | `false` |

Работа без детей диаграммы не образует. Корневая работа лежит на A-0 одна.

## 3. Из связей — в стрелки

Пусть `D` — диаграмма, `K` — её блоки (дети владельца, либо корневая работа для
A-0).

Для каждой связи документа, чей потребитель принадлежит `K`:

| Условие | Стрелка |
|---|---|
| поток производит блок из `K` | внутренняя: выход производителя → названная сторона потребителя |
| поток не производит никто из `K` | граничная: край листа стороны связи → сторона потребителя |

Для каждой связи, чей производитель принадлежит `K`, а поток не потребляет никто
из `K`: граничная от выхода производителя к правому краю листа.

Правила опираются на то, что валидатор уже проверил: потребляемый поток либо
производится на той же диаграмме, либо приходит к родителю **той же стороной**
(`checkBalance`), а всё, что входит в блок и выходит из него, отражено на его
декомпозиции (`checkDecomposition`). Перепроверять это раскладка не обязана —
конвейер идёт лесенкой.

Поток, потребляемый несколькими блоками, даёт по стрелке на каждого потребителя
(ветвления в этой версии нет). Порядок обхода — порядок связей в документе.

### Категория стрелки

Категория определяет шаблон маршрута и вычисляется по положению блоков, а не по
предполагаемой лестнице: координаты мог задать автор.

| Категория | Условие |
|---|---|
| прямая | оба конца на блоках, источник левее приёмника |
| обратная | оба конца на блоках, источник правее приёмника или на одной вертикали |
| граничная входящая | источник — край листа |
| граничная исходящая | приёмник — край листа |

## 4. Точка крепления к блоку

Сторона делится на `n + 1` равных частей, где `n` — число стрелок на этой
стороне блока; `k`-я стрелка садится в `k/(n + 1)`.

| Сторона | Координата крепления |
|---|---|
| вход (слева) | `x = X`, `y = Y + H·k/(n+1)` |
| управление (сверху) | `x = X + W·k/(n+1)`, `y = Y` |
| механизм (снизу) | `x = X + W·k/(n+1)`, `y = Y + H` |
| выход (справа) | `x = X + W`, `y = Y + H·k/(n+1)` |

Порядок `k` — порядок связей в документе. Мера: В6.

## 5. Маршруты

Лист: `7 … 793` по горизонтали, `7 … 437` по вертикали — те же числа, что
использует раскладка блоков.

| Категория | Точки |
|---|---|
| прямая | `(x₁,y₁) → (xm,y₁) → (xm,y₂) → (x₂,y₂)`, где `xm` — середина промежутка между правым краем источника и левым краем приёмника |
| прямая на управление | `(x₁,y₁) → (x₂,y₁) → (x₂,y₂)`: вправо до вертикали порта, вниз в верх блока |
| граничная входящая, слева | `(7,y) → (x₂,y)` |
| граничная входящая, сверху | `(x,7) → (x,y₂)` |
| граничная входящая, снизу | `(x,437) → (x,y₂)` |
| граничная исходящая, справа | `(x₁,y₁) → (793,y₁)` |
| обратная на вход | вниз от выхода, горизонталью по коридору ниже всех блоков, вверх, и в левую сторону приёмника |
| обратная на управление | вверх от выхода, горизонталью по коридору выше всех блоков, вниз в верх приёмника |

Вырождения: если промежуточная координата совпадает с конечной, точка не
дублируется — сегмент из двух точек лучше сегмента из четырёх с нулевой длиной.

Если прямая граничная стрелка задела бы чужой блок, добавляется излом: короткий
отступ от края листа, вертикаль, горизонталь (мера В8, сектор 97 `тест.rsf`).

Коридоры обратной связи берутся из полей листа: снизу — между самым нижним
блоком и `y = 437`, сверху — между `y = 7` и самым верхним. Меры нет, правило
собственное (В9).

## 6. Оверрайд

`layout.arrows`, заданный автором, побеждает целиком: стрелка с этим именем
потока не вычисляется вовсе, ни в одном сегменте. Правило то же, что у блоков
(Р2), и то же место применения — раскладка дописывает только недостающее.

## 7. Номера, живущие только в файле

Не попадают в IR и раздаются генератором.

| Номер | Откуда | Правило |
|---|---|---|
| идентификатор элемента | `MAX(ELEMENT_ID) + 1` | потоки, затем секторы, в порядке документа |
| кросспоинт | `crosspoint_sequence` | по номеру на каждый конец сектора; **один номер на два конца**, сшивающих уровни |
| ординаты | `ordinates__sequence` | по номеру на каждую различную координатную линию сектора; точки на одной линии делят номер |

Обе последовательности после записи увеличиваются в `data/sequences.xml`: Ramus
их не перематывает (В3).

**Сшивка уровней.** Конец «сторона `S` блока `F`» на диаграмме родителя и конец
«край листа стороны `S`» на диаграмме самой `F` с тем же потоком — это один
узел, и номер кросспоинта у них общий (мера В5). Пары ищутся после того, как
все стрелки известны, по ключу «поток + работа + сторона».

## 8. Ключевые ограничения

- Детерминированность: всякий обход идёт по спискам документа, не по отображениям.
- Стрелка не выходит за лист и не пересекает блок работы.
- Документ без связей не даёт ни одной новой строки ни в одной таблице.
- Имя потока переносится посимвольно: запятая, кавычка и возврат каретки уже
  ломали вывод раньше.
