# Implementation Plan: Отказ на моделях со стрелками без имени

**Branch**: `003-unnamed-arrows` | **Date**: 2026-09-09 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/003-unnamed-arrows/spec.md`

## Summary

Стрелка, нарисованная в Ramus и не получившая имени, не выражается входным
языком: идентификатор потока есть его имя (Р4). Сегодня такие стрелки исчезают
из результата декомпиляции молча — теряются шесть секторов в
`ФормированиеТП.rsf` и девять в `тест.rsf`, а автор видит только сводку потерь в
терминах имён атрибутов `.rsf`.

Решение: отвергать такие модели целиком — пустой вывод, код 2, перечень причин,
как у работ без имени.

Технически это один новый вид находки в `internal/rsf/unsupported.go` плюс
приведение перечня проверочных моделей в соответствие. Отказ уже встроен в
`cmd/ramusc/decompile.go`: он вызывает `source.Unsupported()` до всякой печати и
при непустом результате возвращает код 2. Декомпилятор, валидатор, схема и IR не
трогаются.

## Technical Context

**Language/Version**: Go 1.26, модуль `github.com/Zdertis420/autoramus/ramusc`

**Primary Dependencies**: не добавляются. Изменение укладывается в стандартную
библиотеку; три существующие зависимости (`santhosh-tekuri/jsonschema/v6`,
`gopkg.in/yaml.v3`, `golang.org/x/text`) не затрагиваются

**Storage**: файлы `.rsf` (ZIP + XML-таблицы), только чтение

**Testing**: `go test ./...`, эталонные файлы в `ramusc/testdata/golden/`,
табличные проверки по перечню `internal/fixtures`

**Target Platform**: CLI, три платформы кросс-компиляцией; изменение
платформенно-нейтрально

**Project Type**: компилятор/CLI

**Performance Goals**: не предъявляются. Проход по секторам линейный, union-find
почти линейный; крупнейшая известная модель — 103 сектора

**Constraints**: детерминированный вывод (сообщения об отказе обязаны идти в
фиксированном порядке — их читают глазами и сравнивают диффом); поведение на
моделях без безымянных стрелок неизменно побайтово

**Scale/Scope**: четыре проверочные модели, ~120 строк нового кода в одном файле,
правки в перечне моделей, одном тесте и двух документах

## Constitution Check

*GATE: пройден до Phase 0 и перепроверен после Phase 1.*

| Принцип | Как соблюдается |
|---|---|
| **I. Единый источник логики** | Обнаружение живёт в `ramusc`, в `internal/rsf`. GUI получит отказ и код 2 через тот же вызов `ramusc decompile`, ничего своего не заводит |
| **II. Ошибки — данные, а не текст** | Находка остаётся структурой `rsf.Unsupported` с полями `Kind`/`Count`/`Where`, а не собранной строкой. Новый вид **добавляется** к закрытому перечню, ничего не переименовывается. Код возврата 2 — уже принятый для этого исхода. Кодов `internal/diag` изменение не заводит: диагностика описывает входной документ, а не `.rsf`, и второго набора сообщений об одном и том же не возникает |
| **III. Детерминированный вывод** | Порядок находок задаётся сортировкой по стабильному ключу, а не обходом map. Порядок сегментов внутри стрелки и стрелок между собой — по возрастанию идентификатора сектора |
| **IV. Строгий разбор и лесенка конвейера** | Отказ стоит на своей ступени: до перевода в IR и до печати. Неполный результат не выдаётся ни при каких условиях. Границы пакетов не меняются: `decompile` о новой проверке не знает, `rsf` — о `decompile` |
| **V. Эталонные тесты и сверка с реальными файлами** | Правило выведено из трёх настоящих файлов, а не придумано. Четвёртая модель (`тест.rsf`) сделана в самом Ramus и добавляется в перечень. `TestRefusedModelsAreRefused` не даёт пометке `ExpectRefusal` стать тихим выключателем проверки |

Нарушений нет, раздел Complexity Tracking пуст и удалён.

**Оговорка, принятая осознанно**: проверка `TestOutputPasses` («вывод
декомпилятора принимается валидатором») после изменения идёт по одной модели
вместо двух. Это не нарушение принципа V, а объявленная цена решения: спека
фиксирует её в разделе «Последствия решения», и вернуть покрытие сможет только
новая модель, где стрелки названы.

## Порядок работ

Ступенями, каждая проверяема отдельно.

1. **Признак.** Обнаружение секторов без строки `F_SECTOR_STREAM` — по таблице,
   не по результату разбора. Проверка: на трёх моделях находится 0, 6 и 9.
2. **Сборка.** Union-find по кросспоинтам. Проверка: 6 секторов → 1 стрелка,
   9 секторов → 3 стрелки.
3. **Текст.** Описание концов именами работ и сторонами блока. Проверка: строка
   для `тест.rsf` называет «под работа 1» и «под работа 2».
4. **Отказ.** Новый вид в `Unsupported`; CLI меняется нулём строк. Проверка:
   `ramusc decompile examples/тест.rsf` даёт пустой вывод и код 2.
5. **Перечень моделей.** `ExpectRefusal` и `тест.rsf`, снятие записи из
   `remaining`, `make golden` для нового эталона описи.
6. **Документы.** Р18 в `DESIGN-DECISIONS.md`, границы декомпилятора и перечень
   моделей в `CLAUDE.md`.
7. **`make check`** и осознанный коммит эталонов вместе с кодом.

Шаги 1–3 не меняют поведения CLI и могут быть закрыты тестами до шага 4. Шаг 5
ломает `TestNothingIsLostSilently`, пока не снята запись из `remaining`, — это
ожидаемо и служит подтверждением, что перечень действительно управляет
проверками.
