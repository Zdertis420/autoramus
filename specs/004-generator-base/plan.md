# Implementation Plan: Основание генератора — из документа в `.rsf`

**Branch**: `004-generator-base` | **Date**: 2026-09-09 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-generator-base/spec.md`

## Summary

Впервые проект пишет `.rsf`, а не только читает. Заготовка — пустая настоящая
модель IDEF0, сделанная в Ramus, — встраивается в бинарь и наполняется из IR:
имя модели, автор, лист, работы с иерархией, порядком, типом и геометрией.

Стрелки не пишутся: это следующая фича. Файл поэтому заведомо неполон, и
программа обязана сказать об этом вслух — иначе на выходном конце конвейера
заводится та же молчаливая потеря, которую фича 003 убрала на входном.

Разведка сняла с работы почти всю неопределённость: измерено, из каких десяти
строк состоит работа в файле и где лежит имя модели. Заготовку автор вдобавок
пересобрал без справочников — вычищать из неё теперь нечего, и одна ступень
работы отпала целиком.

## Technical Context

**Language/Version**: Go 1.26, модуль `github.com/Zdertis420/autoramus/ramusc`

**Primary Dependencies**: не добавляются. `archive/zip` и `encoding/xml` уже
покрывают запись через `internal/rsf`; `embed` — стандартная библиотека

**Storage**: файлы `.rsf` (ZIP + XML-таблицы); заготовка 30 КБ внутри бинаря

**Testing**: `go test ./...`, эталоны в `ramusc/testdata/golden/`, табличные
проверки по перечню `internal/fixtures`, круг «документ → файл → разбор →
документ» без участия Ramus

**Target Platform**: CLI, три платформы кросс-компиляцией; `go:embed` работает
одинаково всюду и не требует раскладывать файлы рядом с бинарём

**Project Type**: компилятор/CLI

**Performance Goals**: не предъявляются. Крупнейшая известная модель — девять
работ; заготовка распаковывается за миллисекунды

**Constraints**: побайтовая воспроизводимость вывода; поведение `validate`,
`dump` и `decompile` не меняется ни на байт; заготовка считается доверенной и не
проверяется

**Scale/Scope**: один новый пакет, ~350 строк, встраиваемая заготовка, изменение
одной ветки в `cmd/ramusc`

## Constitution Check

*GATE: пройден до Phase 0 и перепроверен после Phase 1.*

| Принцип | Как соблюдается |
|---|---|
| **I. Единый источник логики** | Генерация живёт в `ramusc`. GUI получит файл и коды возврата через тот же вызов, ничего своего не заводит |
| **II. Ошибки — данные, а не текст** | Компиляция начинается с `validate.Source` и выдаёт те же объекты диагностики с теми же кодами (FR-009). Новых кодов не заводится: ошибок входа генератор не порождает — он получает уже проверенный документ. Отказ «нет координат» и предупреждение «связи не записаны» — состояния программы, а не документа, и идут отдельным каналом, как отказ декомпилятора |
| **III. Детерминированный вывод** | `GenerateTime` берётся из заготовки, порядок записей ZIP сохраняется, идентификаторы раздаются в порядке документа, даты не пишутся. Проверка — двойная сборка и сравнение хешей |
| **IV. Строгий разбор и лесенка конвейера** | Генератор запускается, только если проверка не нашла ошибок. Знает про `ir.Model` и `internal/rsf`, о фронтенде не знает. Геометрия — из секции `layout`, как оверрайд поверх (пока отсутствующей) раскладки |
| **V. Эталонные тесты и сверка с реальными файлами** | Заготовка сделана самим Ramus, а не сочинена. Состав строк работы выведен из настоящей модели, а не из документации. Круг проверяется на моделях перечня, а не на придуманных |

Нарушений нет; раздел Complexity Tracking пуст и удалён.

**Оговорка, принятая осознанно.** SC-001 («открывается в Ramus») проверяется
человеком: Ramus — программа с GUI, в `go test` её не встроить. Это ослабление
принципа V, и компенсируется оно двумя способами: оформление работ пишется
значениями, наблюдёнными в настоящих файлах (Р0-1), а всё остальное закрыто
автоматическим кругом, который не требует Ramus вовсе.

**Structure Decision**: заводится ровно один новый пакет — `internal/generate`,
предусмотренный архитектурой с самого начала и до сих пор пустой. Заготовка
лежит в `ramusc/templates/` и попадает в бинарь через `go:embed`; каталог
`templates` в поставке не нужен. Разделение файлов внутри пакета — по сущностям
(модель, работа), а не по таблицам файла: таблиц десять, сущностей две, и
читать код будут по сущностям.

## Порядок работ

Ступенями; каждая ступень проверяема без следующей.

1. **Заготовка.** `go:embed`, открытие в `rsf.File`. Проверка: открытая
   заготовка даёт пустую модель и ноль справочников, а `Bytes()` устойчив к
   повторению. Вычищать содержимое не нужно — заготовка пересобрана чистой;
   проверка на ноль справочников остаётся стражем на случай, если её пересоберут
   снова.
2. **Модель.** Имя в квалификатор работ, автор и лист в свойства, затирание
   текстовых заглушек мастера. Проверка: `dump` собранного файла показывает имя и
   автора из документа, а в свойствах не осталось слов «Определение» и
   «Использовано в».
3. **Работы.** Элементы, имена, иерархия, порядок, тип, прямоугольники,
   постоянное оформление. Проверка: `dump` показывает то же дерево, что в
   документе.
4. **Круг.** Собранный файл декомпилируется, документ сравнивается с исходным по
   переносимым разделам. Проверка идёт по моделям перечня.
5. **CLI.** Компиляция вместо «генератора нет»: коды возврата, `-o`, отказ при
   отсутствии координат, предупреждение о ненаписанных связях.
6. **Документы.** `CLAUDE.md` — состояние пакетов и порядок работ.

Ступени 1–3 не трогают CLI и закрываются тестами пакета. Ступень 5 меняет
пользовательский контракт и делается последней — до неё компиляция продолжает
честно говорить, что генератора нет.

## Риски

| Риск | Что делаем |
|---|---|
| Ramus откажется открыть файл без оформления работ | Оформление пишем сразу постоянными значениями из настоящей модели (Р0-1) |
| Заготовка когда-нибудь будет пересобрана снова, и в неё вернётся лишнее | Проверка «ноль справочников, ноль заглушек» держится независимо от того, что лежит в файле, и падает на возврате мусора |
| Круг окажется слабее, чем кажется | Сравнение идёт по разобранной модели, а не по тексту документа: текст сравнивать бессмысленно, пока не пишутся стрелки, и разделы будут расходиться по существу |
| Правка `internal/validate` заденет существующие выводы | `Source` сохраняется как есть и выражается через новый вход; эталоны диагностики обязаны не измениться ни на байт |
