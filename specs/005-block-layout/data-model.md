# Phase 1. Модель данных

Новых типов в языке, в схеме и в IR не появляется. Раскладка дописывает записи в
`ir.Layout.Functions` — те же самые, которые сегодня пишет автор руками.

---

## Что берётся и что дописывается

| Читается из IR | Зачем |
|---|---|
| `Model.Functions[i].Name` | кого раскладывать |
| `Model.Functions[i].Of` | на чьей диаграмме; пусто — работа корневая |
| `Model.Links` | рёбра для порядка (половинками, см. П-2) |
| `Model.Layout.Functions` | что автор задал сам и трогать нельзя |

| Дописывается | Чем |
|---|---|
| `Model.Layout.Functions` | запись на каждую работу, которой там ещё нет |

Поля записи — те же, что у автора: имя работы, `X`, `Y`, `Width`, `Height`.

---

## Константы, снятые с настоящих файлов

| Что | Значение | Откуда |
|---|---|---|
| Начало диагонали | `(80, 80)` | первая подработа `тест.rsf` |
| Конец диагонали | `(660, 322)` | последняя подработа `тест.rsf` |
| Размер блока | `72 × 50.4` | все подработы `тест.rsf` и две в `ФормированиеТП.rsf` |
| Лист | `7…793` по X, `7…437` по Y | крайние точки стрелок `ИзготовлениеЮбки.rsf` |
| Наименьший блок | `24 × 16.8` | выбрано: ниже блок нечитаем |
| Зазор при сжатии | `6` | выбрано: видимый глазом просвет |

Первые четыре строки — измерение. Две последние — решение, и обозначены как
решение.

## Правила

### П-1. Единица раскладки — диаграмма

Диаграмма — это работа вместе с её непосредственными детьми. У каждой своя
диагональ, свой отсчёт и свой порядок; дети разных родителей друг о друге не
знают (FR-004).

Корневая работа лежит на своей диаграмме одна — это контекстная A-0.

Работа без детей диаграммы не образует: раскладывать нечего.

### П-2. Рёбра собираются из половинок

В IR связи лежат разрозненно: у записи из `in`/`control`/`mechanism` заполнено
только `To`, у записи из `out` — только `From`. Готовых рёбер «работа → работа»
нет.

Ребро `A → B` появляется, когда на одной диаграмме работа `A` производит поток,
который работа `B` потребляет. Поток, приходящий с границы листа, ребра не даёт:
его никто на этой диаграмме не производит.

### П-3. Порядок

Топологическая сортировка по рёбрам П-2. При равенстве — порядок объявления в
документе: он обычно осмыслен (Р3).

Обратные рёбра разрываются: цикл в потоках — это законная обратная связь IDEF0,
а не ошибка, и валидатор её не запрещает. Ребро, ведущее к уже размещённой
работе, на порядок не влияет.

Сортировка обязана быть устойчивой, а обход отображений — не влиять на результат
(принцип III конституции).

### П-4. Размещение по диагонали

Для `n` блоков на диаграмме, `i` от нуля:

```
шагX = (660 − 80) / (n − 1)
шагY = (322 − 80) / (n − 1)
X(i) = 80 + i × шагX
Y(i) = 80 + i × шагY
```

При `n = 1` формула вырождается: единственный блок ставится в центр листа.

### П-5. Размер и сжатие

По умолчанию `72 × 50.4`. Когда горизонтальный шаг перестаёт вмещать блок:

```
ширина = max(24, min(72, шагX − 6))
высота = ширина × 0.7
```

Доля `0.7` — это ровно `50.4 / 72`, то есть пропорция блока сохраняется.

Границы поведения посчитаны:

* до девяти блоков сжатие не включается — диагональ разносит их по горизонтали,
  и вертикальная теснота с шести блоков безвредна;
* с десяти блоки мельчают и продолжают не накладываться;
* с двадцати шести шаг становится меньше наименьшего блока, и наложение
  возвращается. Это названная граница (FR-003), а не недосмотр.

### П-6. Заданное автором не трогается

Работа, у которой уже есть запись в `layout`, пропускается целиком: ни значения,
ни положение записи в списке не меняются. Новые записи дописываются в конец, в
порядке размещения.

Из этого следует FR-007: документ с полной геометрией проходит раскладку без
единого изменения, и файл получается тот же побайтово.

### П-7. Чего раскладка не делает

* не трогает `Layout.Arrows` — стрелок она не раскладывает;
* не заводит диагностику: документ к ней приходит уже проверенным;
* не знает про `.rsf`, ZIP и XML — на входе и выходе только IR;
* не проверяет, что все работы получили геометрию. Это делает генератор своей
  прежней проверкой — дешёвая страховка от тихой записи блока в `(0, 0)`.
