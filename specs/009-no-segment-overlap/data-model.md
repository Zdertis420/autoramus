# Data Model: каналы стрелок

**Фича**: 009-no-segment-overlap

Сущности живут внутри `internal/layout` и наружу не выходят: пакет по-прежнему
принимает `*ir.Model` без геометрии и отдаёт его же с геометрией (Р16). Ни в IR,
ни в схеме входного языка, ни в формате `.rsf` новых полей не появляется —
меняются только значения координат в `layout.arrows[].segments[].points`.

## Линия (канал)

Прямая, вдоль которой идёт сегмент. Единица разведения.

| Поле | Тип | Смысл |
|---|---|---|
| `diagram` | строка | владелец диаграммы; пусто — контекстная A-0 |
| `axis` | `V` \| `H` | вертикаль (общий `x`) или горизонталь (общий `y`) |
| `coord` | число | сама координата |

Линии разных диаграмм независимы: они на разных листах и наложиться не могут.
Вертикаль и горизонталь пересекаются в точке — это разрешено и никого не
интересует.

## Заявка

Требование одной стрелки на одну линию. **Единица, которая двигается.**

| Поле | Тип | Смысл |
|---|---|---|
| `arrow` | поток + диаграмма | чья заявка; ключ тот же, что у `arrowKey` |
| `line` | линия | где стрелка хочет лежать (каноническая координата) |
| `segments` | список | её сегменты на этой линии |
| `span` | `[lo, hi]` | объединённая протяжённость вдоль линии |
| `pinned` | булево | закреплена — двигать нельзя |
| `key` | (индекс потока, индекс сегмента) | стабильный ключ сортировки |

Заявка, а не сегмент, потому что сегменты одной стрелки на одной линии обязаны
ехать вместе:

* магистраль ветвления — три сегмента на одной горизонтали; сдвинуть один
  значит разорвать линию;
* узел ветвления — одна точка (`TestCrosspointIsOnePoint`); сдвинув сегмент
  магистрали отдельно от отвода, получишь две точки с одним номером — ровно ту
  ошибку, которую закрыла фича 007.

**Правило перемещения**: заявка едет так, что каждая точка её сегментов меняет
одну координату — `x` у вертикальной линии, `y` у горизонтальной. Соседние
сегменты ломаной удлиняются или укорачиваются, узловые точки едут вместе с
магистралью, форма ломаной сохраняется.

### Закрепление

Заявка закреплена, если хотя бы один её сегмент упирается концом в место, откуда
его сдвиг уведёт:

| Сегмент | Упирается в | Почему закреплён |
|---|---|---|
| вертикаль | верх или низ блока | приход на управление или механизм; сдвиг по `x` отцепит стрелку |
| горизонталь | левую или правую сторону блока | приход на вход, уход с выхода; сдвиг по `y` отцепит |
| вертикаль | верхний или нижний край листа | вход на диаграмму; сдвиг уведёт точку входа |
| горизонталь | левый или правый край листа | то же |

Закреплённая заявка в раздаче участвует **как занятая линия**: свободные её
обходят, сама она стоит.

## Занятость

Что на линии уже лежит. Складывается из трёх источников:

1. заявки, уже получившие эту линию в этом проходе;
2. закреплённые заявки;
3. **сегменты, написанные автором** в секции `layout` (Р2, FR-009) — они в
   раздаче не участвуют, но место занимают;
4. блоки диаграммы: линия, проходящая внутри блока, свободной не считается.

Две заявки делят линию **мирно**, если их `span` не перекрываются по длине.
Стрелка, идущая по той же вертикали, но на другой высоте, никому не мешает, и
разводить её незачем — иначе рисунок разъезжался бы без нужды (FR-008).

## План каналов

Итог прохода: отображение «заявка → выданная координата». Строится и
применяется на одной диаграмме за раз, диаграммы независимы.

### Порядок раздачи

1. Заявки одной линии сортируются по `key`.
2. Первая по ключу получает каноническую координату — ту, что формула даёт
   сегодня.
3. Каждой следующей, чей `span` перекрывается с уже выданным, координаты
   предлагаются по очереди: `c ± step`, `c ± 2·step`, … Берётся первая, где
   свободно.
4. Свободной нет — берётся каноническая. Наложение остаётся, поведение названо
   (FR-010).

Координата считается занятой, если на ней уже лежит перекрывающаяся по `span`
заявка, или если сдвинутый сегмент после переезда пересечёт блок
(`crossesAny`).

### Инварианты

| Инвариант | Требование |
|---|---|
| Ни одна точка не выходит за лист `7…793` × `7…437` | FR-010 |
| Заявки одной стрелки между собой не разводятся | FR-003 |
| Заявка с одним претендентом не двигается вовсе | FR-008 |
| План зависит только от текста документа | FR-005 |
| Число точек и сегментов не меняется — меняются только значения | FR-011 |

## Что НЕ является сущностью этой фичи

**Номер ординаты** (`X_ORDINATE_ID` / `Y_ORDINATE_ID`). Живёт в генераторе,
раздаётся по значению координаты на каждый сектор (`generate/ids.go: lines`) и
следует за координатами сам. Раскладка про него не знает и знать не должна
(Р16). Попытка сделать его единицей разведения — прочтение формулы «канал =
ордината» в обратную сторону — привела бы к слиянию стрелок, а не к разведению
(FR-006).
