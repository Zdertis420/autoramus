# Контракт с файлом: какие строки пишутся

Состав снят с настоящих моделей (`research.md`, В1–В12). Везде
`VALUE_BRANCH_ID = 0`; в `elements` — `CREATED_BRANCH_ID = 0`,
`REMOVED_BRANCH_ID = 2147483647`. Идентификаторы атрибутов ищутся **по имени**:
номера свои в каждом файле.

## Поток — три строки

| Таблица | Атрибут | Поля |
|---|---|---|
| `elements` | — | `QUALIFIER_ID` = `F_STREAMS`, `ELEMENT_NAME` пусто |
| `attribute_hierarchicals` | `HierarchicalAttribute` | `PARENT_ELEMENT_ID = -1`, `PREVIOUS_ELEMENT_ID` = предыдущий поток или `-1`, `ICON_ID = -1` |
| `attribute_texts` | `F_STREAM_NAME` | `VALUE` = имя потока |

Порядок потоков — порядок секции `flows`. Имя живёт в `F_STREAM_NAME`, а не в
`ELEMENT_NAME` и не в атрибуте-имени квалификатора работ.

## Сектор — от шести строк

| Таблица | Атрибут | Поля |
|---|---|---|
| `elements` | — | `QUALIFIER_ID` = `F_SECTORS`, `ELEMENT_NAME` пусто |
| `attribute_other_elements` | `F_FUNCTION_SECTOR` | `OTHER_ELEMENT` = элемент диаграммы: элемент модели для A-0, работа-родитель для прочих |
| `attribute_other_elements` | `F_SECTOR_STREAM` | `OTHER_ELEMENT` = поток |
| `attribute_sector_borders` | `F_SECTOR_BORDER_START` | конец, см. ниже |
| `attribute_sector_borders` | `F_SECTOR_BORDER_END` | конец, см. ниже |
| `attribute_sector_points` | `F_SECTOR_POINTS` | по строке на точку, см. ниже |
| `attribute_sector_properties` | `F_SECTOR_PROPERTIES` | подпись, см. ниже |
| `attribute_sectors` | `F_SECTOR_ATTRIBUTE` | оформление, см. ниже |

Иерархической строки у сектора нет — проверено на всех трёх моделях.

### Конец сектора

| Поле | Конец на блоке | Конец на краю листа |
|---|---|---|
| `FUNCTION` | элемент работы | `-1` |
| `FUNCTION_TYPE` | сторона | `-1` |
| `BORDER_TYPE` | `-1` | сторона края |
| `CROSSPOINT` | номер узла | номер узла |
| `TUNNEL_SOFT` | `0` | `0` |

Стороны — один словарь на оба случая: `0` выход (справа), `1` механизм (снизу),
`2` вход (слева), `3` управление (сверху).

Номер кросспоинта стоит у **любого** конца, включая прицепленный к блоку.
Конец на блоке родителя и конец на краю листа дочерней диаграммы с тем же
потоком и той же стороной делят **один** номер: этим в файле выражено
согласование уровней.

### Точка

| Поле | Значение |
|---|---|
| `POSITION` | номер в ломаной, с нуля |
| `POINT_TYPE` | `-1` |
| `X_POSITION`, `Y_POSITION` | координаты |
| `X_ORDINATE_ID`, `Y_ORDINATE_ID` | номер координатной линии; точки с одинаковым `x` делят `X_ORDINATE_ID`, с одинаковым `y` — `Y_ORDINATE_ID` |

Общих ординат между разными стрелками в этой версии нет: разведение по каналам
за границами фичи.

### Подпись

| Поле | Значение |
|---|---|
| `SHOW_TEXT` | `1` |
| `TEXT_X`, `TEXT_Y` | середина ломаной |
| `TEXT_WIDTH` | ≈ `4.3` на руну имени |
| `TEXT_HIEGHT` | `9.80078125` (одна строка при шрифте `Dialog 10`) |
| `SHOW_TILDA` | `0` |
| `TILDA_POS` | `0.0` |
| `TRANSPARENT` | `1` |

Флаг и рамка ходят парой: где `SHOW_TEXT = 0`, там вся рамка нулевая. Обратное
тоже верно, и писать `SHOW_TEXT = 1` с нулевой рамкой в настоящих файлах не
встречается.

### Оформление

| Поле | Значение |
|---|---|
| `SHOW_TEXT` | `1` |
| `TEXT_ALIGMENT` | `0` |
| `CREATE_POS` | `0.0` |
| `CREATE_STATE` | `-1` |
| `ALTERNATIVE_TEXT` | пусто |
| `VISUAL_ATTRIBUTES` | постоянная строка в 140 знаков, одинаковая во всех трёх моделях |

Смысл `VISUAL_ATTRIBUTES` не разобран, и разбирать его незачем: значение
постоянно, как и `F_VISUAL_DATA` у работ, и детерминированности не мешает.

## Последовательности

`data/sequences.xml` после записи содержит увеличенные `ordinates__sequence` и
`crosspoint_sequence` — на число выданных номеров. Ramus эти две
последовательности сам не перематывает.

## Чего не пишется

- `attribute_decomposition_types` у работ — как и до этой фичи;
- даты (`F_CREATE_DATE`, `F_REV_DATE`) — брать их неоткуда, а текущее время
  сломало бы детерминированность;
- кросспоинты как отдельные элементы ветвления;
- туннельные признаки, отличные от `0`.
