# Контракт: форма дерева ветвления

## 1. Внешние интерфейсы не меняются

| Поверхность | Изменение |
|---|---|
| CLI `ramusc`: команды, флаги, коды возврата | нет |
| `--json` диагностики, коды `internal/diag` | нет |
| Входной язык, `model.schema.json` | нет |
| IR (`internal/ir`) | нет |
| Формат `.rsf`: таблицы, колонки, последовательности | нет |
| `layout.Apply(m *ir.Model)` | подпись та же |

Меняется **геометрия** сегментов ветвящихся стрелок и то, из каких узлов они
выходят. Число сегментов, узлов и связей не меняется ни на одной модели.

Новых диагностик нет: форма рисунка — не свойство входа, и сообщать о ней
пользователю нечего.

## 2. Форма, которую обязано давать дерево

Поток, приходящий на диаграмму извне к `k` работам одной стороной (`k ≥ 2`):

```
1 сегмент     край листа → первый узел                  (вход)
k−2 сегмента  узел → узел вдоль хребта                  (хребет)
1 сегмент     последний узел → работа на продолжении    (замыкание)
k−1 сегмент   узел → своя работа, с поворотом внутри    (ветки)
──────────────────────────────────────────────────────
2k−1          всего
```

Хребет **перпендикулярен краю листа**: у управления и механизма вертикален, у
входа горизонтален. Ветка идёт вдоль полосы своего узла до координаты точки
крепления, затем заворачивает в работу.

При `k = 1` дерева нет: одна линия, ноль узлов.

## 3. Инвариант, который проверяется тестом

```go
// TestBranchCarriesItsOwnCorner — у каждой ветки свой поворот.
//
// Ветка, цель которой не лежит на продолжении хребта, обязана иметь ровно один
// собственный поворот: ломаную из трёх точек. Голых двухточечных отводов не
// остаётся — именно они рисуются у Ramus без скругления.
func TestBranchCarriesItsOwnCorner(t *testing.T)
```

Правила проверки:

1. Ветка — сегмент, идущий из узла в работу.
2. Ветка с тремя точками и одним поворотом — норма.
3. Ветка с двумя точками допустима **только** если её точка крепления лежит на
   хребте (вырожденный случай, `head`).
4. Проверка идёт по всему набору `documents()`; новый документ добавляется в
   перечень, код теста не трогается.

```go
// TestTurnsAreInsidePolylines — счёт поворотов внутри и на стыках.
//
// Считает то же, что evidence/turns.py снаружи компилятора, и служит для сверки
// с ним: расхождение значит, что раскладка думает одно, а в файл доехало другое.
func TestTurnsAreInsidePolylines(t *testing.T)
```

## 4. Что обязано уцелеть

Проверяется существующими тестами; фича не вправе их сломать.

| Инвариант | Где сторожится | Переживает ли новую форму |
|---|---|---|
| Сегментов `2k−1`, вход один, узлов `k−1`, отводов `k` | `TestTreeShape` | **да**, все четыре числа те же |
| Узел — одна точка | `TestTreeNodesAreOnePoint`, `TestCrosspointIsOnePoint` | да |
| Без ветвления узлов не заводится | `TestNoNodesWithoutBranching` | да |
| Дерево детерминировано | `TestTreeIsDeterministic` | да |
| Сегменты разных стрелок не накладываются | `TestNoSegmentOverlap` (фича 009) | **проверить**: полосы новые |
| Стрелка не идёт сквозь блок, не наискось, не за листом | `TestGeometryIsLawful` | **проверить**: ветки длиннее |
| Каждая связь нарисована | `TestEveryLinkDrawn` | да |
| Авторская геометрия не тронута | `override_test.go` | да |
| Две сборки дают побайтово равные файлы | принцип III | да |

`TestTreeShape` проходит **без правки кода**: он считает количества, а они у
обеих форм одинаковы. Его комментарий описывает старый рисунок посегментно и
устареет — это правка текста, а не проверки.

## 5. Эталоны

`testdata/golden/` сняты с `examples/ИзготовлениеЮбки.rsf` — файла, который мы
только читаем. Форма нашего дерева на них не влияет, и `make golden` этой фиче
не нужен. Поехавший эталон — повод разбираться, а не переписывать.

## 6. Сверка снаружи

`evidence/turns.py` считает повороты по собранному `.rsf`, независимо от
раскладки. Ожидаемые числа на `examples/chakhokhbili.yaml`:

| | до | после |
|---|---|---|
| Поворотов внутри ломаной | 23 | 38 |
| Поворотов на стыке | 22 | 22 |
| Веток без своего поворота | 22 | 0 |

Повороты на стыке остаются: это ответвления, где линия и должна расходиться под
прямым углом. У самого Ramus их 4–17 на файл.
