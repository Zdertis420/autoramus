# Research: Стрелка никогда не идёт сквозь блок

Фаза 0. Открытых вопросов в спецификации нет (Clarifications). Неизвестные
плана — какие маршруты строятся без проверки препятствий, существует ли чистый
путь всегда и куда в конвейере поставить предупреждение — сняты с кода и
прогонов.

Скрипт: `evidence/through.py` — отрезки стрелок сквозь блоки по готовому `.rsf`.

## И1. Какие маршруты строятся без проверки препятствий

Разбор `internal/layout/route.go` и `tree.go`:

| Категория | Где строится | Проверка препятствий |
|---|---|---|
| выход → вход (прямая) | `forward`, шаблон «вправо, вниз, вправо» по `middle` | **нет** |
| выход → управление (прямая) | `forward`, три точки; обход сверху — только когда приёмник выше выхода (фича 012) | **нет** против промежуточных блоков |
| выход → механизм (прямая) | `forward` через `corridorBelow` | **нет** против промежуточных блоков на вертикали `middle` |
| обратная связь | `feedback`, коридоры; на вход — `pick(lanes)` | частично |
| край → вход | `fromBorder`: прямая, при задевании — `pick(lanes)` | есть |
| край → управление, механизм | `fromBorder`: прямая, при задевании — коридор | есть, без перебора |
| выход → край справа | прямая горизонталь | **нет** |
| ветка дерева от порта | `portTree` → `route()` | как у `route()` |
| ветка дерева от края | `tree` — своя геометрия | **нет** |
| сдвиг по каналам | `channels` | есть: кандидат, заезжающий в блок, отвергается |

«Курица с луком» на «чахохбили» — прямая связь выход → вход через одну
ступень: вертикаль `middle` стоит ровно в центре пропущенного блока (дефект,
известный с фичи 009).

## И2. Чистый путь в собственной лестнице существует всегда

В лестнице, которую расставила раскладка (фичи 005, 012):

* **коридор над всеми блоками** — `min(top) − stub`, **под всеми** —
  `max(bottom) + stub`; оба внутри листа (верх лестницы 80, низ 372.4, лист
  7…437); ни один блок их не пересекает по построению;
* **вертикаль сразу за источником** `x = source.right + stub`: блоки левее
  кончаются раньше, блоки правее начинаются не ближе `gapX ≥ gap = stub`
  (страховка фичи 012) — вертикаль в худшем случае касается соседа, не входя в
  него;
* **вертикаль сразу перед приёмником** `x = target.left − stub` — то же
  рассуждение в зеркале.

Отсюда путь из пяти отрезков, который не задевает ни одного блока ни при каком
числе работ и ни при каких размерах:

```
выход → (source.right+stub, y_out) → (…, коридор) → (target.left−stub, коридор)
      → (…, y_in) → вход
```

Для входа сверху (управление) последний спуск — вертикаль `x_port` из коридора
над блоками: левее приёмника в его колонке блоков нет. Для механизма — то же
снизу. Для выхода к правому краю — из коридора к краю листа.

Это доказательство FR-005 для диаграммы без авторских блоков. С авторскими
блоками оно держится, пока рядом с источником и приёмником есть свободная
вертикаль; FR-010 (авто-блок не ложится на авторский) даёт авто-блокам зазор,
а случай «автор сам поставил свои блоки вплотную или внахлёст» — названная
граница по FR-005.

## И3. Авто-блок на авторском: `skirt-full`

Раскладка расставляет лестницу, не глядя на авторские блоки (`Apply`,
`known[name]` → `continue`). В `skirt-full` автор поставил «Сшивание деталей»
в 369…471 × 201…276, а ступень лестницы «Добавления фурнитуры» — 466.7…538.7 ×
241…292: перекрытие 4.3 × 35. Стрелки между ними («Фурнитура», «Собранное
изделие») проходят сквозь оба — 5 отрезков.

Сдвиг авто-блока вправо на правый край авторского плюс зазор 24 даёт 495…567;
следующая ступень, «Приём заказа», стоит в 660 — перекрытия нет. Авторская
ветка «Правил изготовления» приходит в верх «Добавления фурнитуры» в точке
(503, 241) — после сдвига она по-прежнему над его верхней стороной.

## И4. Куда поставить предупреждение

* Проверить авторскую стрелку против блоков можно только после раскладки:
  блок, сквозь который она идёт, может быть расставлен раскладкой.
* `validate.Source` и `validate.Build` — единственный вход, который видят
  `TestGolden` и `TestEveryCodeIsExercised`: код диагностики, возникающий
  после них, эталоном не проверить.
* `ramusc validate` раскладку сегодня не запускает; `ramusc <file>` запускает
  её в `build()` после печати диагностики. Двух наборов сообщений быть не
  должно — значит, предупреждение должно появляться там же, где все прочие.
* Раскладка **идемпотентна**: повторный `layout.Apply` на уже разложенной
  модели ничего не меняет (проверено на «чахохбили», `skirt-full`,
  «бриллиантах» — `Layout` побайтово тот же): всё, что она дописала, при
  повторе выглядит авторским.
* У точек IR есть позиция в документе (`ir.Point.Pos`), у сегмента — путь.

## Решения

### Р-1. Один обходчик для всех категорий

**Decision**: функция обхода в `internal/layout`: по началу (точка и
направление выхода), концу (точка и направление входа) и блокам диаграммы
перебирает конечный упорядоченный список маршрутов и берёт первый, не
задевающий ни одного блока:

1. прежний шаблон категории — если чист, он и остаётся (FR-003);
2. тот же шаблон с вертикалью (или горизонталью) из `lanes()` — ближайшей к
   прежней, как в `pick()`;
3. путь через коридор над блоками, затем под блоками (И2).

Звать его везде, где сегодня шаблон строится без проверки (И1): `forward` для
всех трёх сторон, выход к правому краю, ветки дерева от края листа.

**Rationale**: `pick()` и `lanes()` уже есть и сняты с рисунка Ramus (сектор 97
«теста»); их не хватало только в части категорий. Перебор конечен и
упорядочен — принцип III и запрет на поиск пути соблюдены. Последний кандидат
чист всегда (И2), поэтому «названной границы» для собственной лестницы нет
(FR-005).

**Alternatives considered**:

* общий поиск пути (A*, видимость) — отвергнуто: запрещён конституцией
  духом («задача, решаемая сортировкой») и даёт не-IDEF0-шный рисунок;
* менять лестницу, чтобы перешагивающих связей не было, — отвергнуто: порядок
  работ задан потоками, а связь через ступень — законный рисунок.

### Р-2. Ближайший к прежнему — порядок кандидатов

**Decision**: кандидаты перебираются от прежнего шаблона к коридорам; внутри
шага 2 — по близости полосы к прежней (как `lanes()`); из коридоров —
ближайший к выходу по вертикали. Первый чистый и берётся.

**Rationale**: FR-004 и US2: «Курица с луком» получает полосу в соседнем
промежутке — те же четыре точки, что и прежде, изломов не прибавляется.
Коридор — самый дальний от прежнего рисунка вариант и потому последний.

### Р-3. Страховка после разведения по каналам

**Decision**: проверку «ни один отрезок не в блоке» держит тест по собранному
файлу; разведение по каналам уже отвергает кандидата, заезжающего в блок, и
правки не требует. Отдельного прохода-чинильщика после каналов нет.

**Rationale**: проход, чинящий последствия предыдущего, скрывал бы дефект;
тест покажет, если каналы когда-нибудь заведут стрелку в блок.

### Р-4. Авто-блок обходит авторские

**Decision**: в `Apply` после расчёта лестницы авто-блоки диаграммы по порядку
лестницы сдвигаются вправо за правый край каждого блока, на который налезают
(авторского или уже сдвинутого авто), с зазором `blockClearance = 24`; если
так выходит за правый край листа — вниз за нижний край, с тем же зазором.
Не вышло и так — названная граница: блок стоит на ступени лестницы.

`blockClearance = 4 · gap`: вертикаль стрелки посередине и по два шага
разведения каналов (по 6) с каждой стороны. Решение, а не мера.

**Rationale**: FR-010. Авторские блоки не двигаются (Р2); авто-блок, которому
не мешают, остаётся на месте — документы без авторских блоков не меняются.

**Alternatives considered**: перестроить всю лестницу вокруг авторских блоков
— отвергнуто: меняет положение всех авто-блоков, даже не задетых, и ломает
`TestPartialOverride` («закрепление соседа не двигает остальных»).

### Р-5. Предупреждение — ступень конвейера после раскладки

**Decision**:

* `validate.Build` после смысловых проверок без ошибок запоминает авторские
  сегменты, вызывает `layout.Apply` и последней ступенью — проверку
  геометрии: для каждого авторского сегмента, отрезок которого проходит
  сквозь блок своей диаграммы, — предупреждение нового кода
  `arrow_through_block` с позицией первой точки этого отрезка;
* `validate.Source` — через `Build`, как и сейчас;
* `build()` в `cmd/ramusc` получает уже разложенную модель; его вызов
  `layout.Apply` остаётся и ничего не меняет (раскладка идемпотентна, И4) —
  или убирается; решение — в задачах, с тестом на побайтовое совпадение.

**Rationale**: И4 — только так предупреждение одинаково в `validate` и в
компиляции, видно в `--json` и проверяется эталоном. Лесенка соблюдена:
раскладка запускается, только если ошибок нет; проверка геометрии выдаёт
только предупреждения и сборку не останавливает.

**Alternatives considered**:

* предупреждение в `cmd` после `build()` — отвергнуто: `validate` его не
  увидит, эталоном не проверить (два набора сообщений);
* проверять авторскую стрелку только против авторских блоков, до раскладки —
  отвергнуто: блок, сквозь который она идёт, чаще расставлен раскладкой.

### Р-6. Проверка — по собранному файлу, без исключений

**Decision**:

* `TestNoArrowThroughBlock` — по собранному файлу, на всём наборе
  (`testdata/documents/*.yaml` перечнем и примеры поставки): ни один отрезок
  сквозь блок своей диаграммы, кроме авторских стрелок;
* `overlapDocuments` в `internal/layout/channel_test.go` больше не нужен —
  «чахохбили» переходит в общий перечень (FR-007);
* `TestAutoBlocksAvoidAuthored` — авто-блоки не перекрывают авторские
  (`skirt-full` и синтетическая модель);
* `TestDetourIsNearest` — «Курица с луком» получает маршрут из тех же четырёх
  точек (изломов не прибавилось, US2);
* модель `testdata/models/arrow-through-block.yaml` с эталоном — для нового
  кода (FR-012, `TestEveryCodeIsExercised`).
