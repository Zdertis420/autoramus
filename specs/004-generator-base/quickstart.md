# Phase 1. Как убедиться, что работает

Все команды — из каталога `ramusc/`.

## До начала

```bash
make check                                   # исходное состояние обязано быть зелёным
go run ./cmd/ramusc dump templates/template-idef0.rsf | head -20
```

Второе печатает пустую модель: квалификатор работ «Имя модели», ноль работ, ноль
потоков, ноль справочников. Это точка отсчёта.

## Слепок «как было»

```bash
go run ./cmd/ramusc dump ../examples/ИзготовлениеЮбки.rsf > /tmp/before-yubka.dump
go run ./cmd/ramusc decompile ../examples/ИзготовлениеЮбки.rsf > /tmp/yubka.yaml
```

Второй файл — тот самый документ, на котором проверяется круг: он единственный
из перечня несёт полную раскладку.

## Сценарий 1 — заготовка чиста (FR-015, П-6)

```bash
go test ./internal/generate -run TestTemplate -v
```

Ожидается: заготовка читается, даёт ноль работ и **ноль справочников**, а после
записи модели свойства не содержат ни «Определение», ни «Использовано в».

Проверка на ноль справочников сейчас выполняется сама собой — заготовка
пересобрана чистой. Она стоит здесь как страж: если заготовку пересоберут снова
и каталоги вернутся, это будет видно сразу, а не в Ramus у автора.

## Сценарий 2 — модель и работы попадают в файл (US1)

```bash
go run ./cmd/ramusc /tmp/yubka.yaml -o /tmp/out.rsf; echo "код: $?"
go run ./cmd/ramusc dump /tmp/out.rsf > /tmp/after.dump
diff /tmp/before-yubka.dump /tmp/after.dump
```

Ожидается: код 0, предупреждение о ненаписанных связях на stderr. Дифф покажет
расхождения **только** в разделах потоков и секторов — работы, их имена,
иерархия и прямоугольники обязаны совпасть построчно. Идентификаторы работ могут
отличаться: их назначает компилятор.

## Сценарий 3 — круг замыкается (US2)

```bash
go test ./internal/generate -run TestRoundTrip -v
```

Ожидается: документ → файл → разбор → документ сохраняет имя модели, автора,
лист, набор работ, иерархию, порядок и геометрию.

## Сценарий 4 — две сборки, один файл (SC-002, FR-007)

```bash
go run ./cmd/ramusc /tmp/yubka.yaml -o /tmp/a.rsf
go run ./cmd/ramusc /tmp/yubka.yaml -o /tmp/b.rsf
cmp /tmp/a.rsf /tmp/b.rsf && echo "побайтово одинаковы — верно"
```

## Сценарий 5 — нет координат, нет файла (FR-013, П-5)

```bash
rm -f /tmp/nolayout.rsf
go run ./cmd/ramusc ../examples/skirt.yaml -o /tmp/nolayout.rsf; echo "код: $?"
test ! -e /tmp/nolayout.rsf && echo "файл не создан — верно"
```

Ожидается: код 2, перечень работ без координат, файла нет. `skirt.yaml` секции
`layout` не содержит — это и есть настоящий случай, а не выдуманный.

## Сценарий 6 — невалидный документ (FR-009, FR-010)

```bash
rm -f /tmp/bad.rsf
go run ./cmd/ramusc testdata/models/no-root.yaml -o /tmp/bad.rsf; echo "код: $?"
test ! -e /tmp/bad.rsf && echo "файл не создан — верно"
go run ./cmd/ramusc testdata/models/no-root.yaml --json | head -5
```

Ожидается: код 1, та же диагностика, что у `validate`, файла нет.

## Сценарий 7 — проверка человеком (SC-001)

Единственное, что не автоматизируется.

1. Открыть `/tmp/out.rsf` в Ramus.
2. Убедиться: модель называется «Изготовление юбки», автор «Ножкин А.М.»,
   в дереве четыре работы в том же порядке, блоки стоят на своих местах.
3. Убедиться: справочников нет ни одного, в свойствах модели нет слов
   «Определение» и «Использовано в».
4. Стрелок нет — так и должно быть на этой ступени.

Если Ramus покажет работы без шрифта или цвета — значит постоянные значения
оформления (Р0-1) подобраны неверно, и это единственное место, где ошибку не
поймает ни один автоматический тест.
