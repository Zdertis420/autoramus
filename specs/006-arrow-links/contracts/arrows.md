# Контракты: раскладка, генератор, CLI

## 1. `internal/layout` — вход и выход прежние

Подпись не меняется:

```go
// Apply раздаёт геометрию тому, чего автор не задал: блокам — координаты,
// стрелкам — маршруты.
func Apply(m *ir.Model)
```

**Вход**: `ir.Model`, прошедшая валидатор. Геометрия может быть задана частично.

**Выход**: та же модель. К уже заполняемому `m.Layout.Functions` добавляется
`m.Layout.Arrows` — по элементу на стрелку, которой автор не задал сам.

**Что пакет по-прежнему не знает**: ZIP, XML, имена таблиц, идентификаторы
элементов, номера кросспоинтов и ординат. Всё это — про файл, а не про
геометрию.

**Порядок проходов**: порядок блоков → геометрия блоков → маршруты стрелок.
Третий проход читает результат второго и потому не может идти раньше.

**Инварианты выхода**:

- у каждой связи документа есть стрелка, если автор не задал её сам;
- каждый сегмент назван диаграммой (`Segment.On` плюс `Context` для A-0);
- каждый конец — либо блок со стороной, либо край листа; узлов не создаётся;
- точки ломаной лежат в пределах листа;
- соседние точки отличаются ровно одной координатой (ломаная ортогональна);
- при повторном вызове на одной модели результат тот же.

## 2. `internal/generate` — что добавляется в файл

```go
func File(m *ir.Model) (*rsf.File, error)
```

Подпись не меняется. Добавляется запись потоков и секторов; порядок записи —
модель, работы, потоки, секторы.

**Требование к входу**: у каждой связи документа есть стрелка в
`m.Layout.Arrows`. Пустое место здесь — не мелочь, которую можно восполнить: это
молчаливая потеря связи, и она даёт отказ с кодом 2, как сегодня даёт отказ
работа без координат.

**Что генератор раздаёт сам**: идентификаторы элементов, номера кросспоинтов и
ординат, значения оформления. Раскладка про них не знает.

## 3. `internal/rsf` — новое

```go
// Sequences читает значения последовательностей из data/sequences.xml.
func (f *File) Sequences() (map[string]int64, error)

// SetSequence переписывает одно значение, не трогая остального содержимого.
func (f *File) SetSequence(name string, value int64) error
```

`data/sequences.xml` — java-Properties, а не таблица, и лежит в `File.Raw`
байтами. Правка точечная: комментарий, DOCTYPE, порядок записей и переводы строк
сохраняются. Файл без правок обязан собраться побайтово тем же.

Имена, которые нас касаются: `ordinates__sequence`, `crosspoint_sequence`.
Прочие Ramus перематывает сам (`RSF-FORMAT.md` §1).

## 4. CLI — что меняется для автора

**Уходит** предупреждение, которое команда печатала после каждой удачной сборки:

```
model.yaml: связи в .rsf пока не записываются
  объявлено потоков: 11
  в файле будут только блоки работ; стрелки появятся следующей версией
```

**Не меняется**: коды возврата, поведение `validate`, `dump`, `decompile`,
формат `--json`, набор кодов диагностики. Новых сообщений об ошибках автора не
появляется: всё, что можно было сказать про связи, валидатор говорит и сегодня.

**Остаётся отказом** (код 2, файл не создаётся) случай, когда генератору нечего
записать в сектор: это дефект компилятора, а не ошибка документа, и молча
выпустить файл без стрелки нельзя.

## 5. Круг «документ → файл → разбор → документ»

Расширяется на связи. После этой фичи из собранного файла обязаны вычитываться:

| Что | Чем читается |
|---|---|
| имена потоков и их порядок | `rsf.Model.Streams()` |
| сегменты, их диаграммы и потоки | `rsf.Model.Sectors()` |
| концы: блок со стороной, край листа | `rsf.Border` |
| ICOM каждой работы | `rsf.Model.ICOM()` |
| связи входного языка | `decompile` |

Сверка идёт по связям, а не по байтам: `ИзготовлениеЮбки.rsf` содержит ручную
геометрию, и повторить её координаты автораскладка не обязана и не должна.
