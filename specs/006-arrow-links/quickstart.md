# Как убедиться, что связи доехали

Проверки идут от дешёвых к дорогим: сначала то, что видит `go test`, потом то,
что видно только глазами в самом Ramus.

## 0. Собрать

```bash
cd ramusc
make check        # форматирование, go vet, тесты
make build        # даёт ./ramusc
```

## 1. Предупреждения больше нет (FR-013, SC-007)

```bash
./ramusc ../examples/skirt.yaml -o /tmp/skirt.rsf
```

**Ожидается**: файл собран, поток ошибок пуст. До этой фичи здесь печаталось
«связи в .rsf пока не записываются» и число объявленных потоков.

## 2. Связи читаются обратно (FR-012, SC-002)

```bash
./ramusc dump /tmp/skirt.rsf
```

**Ожидается**: раздел потоков содержит все одиннадцать имён `skirt.yaml`; раздел
секторов непуст; у каждой работы виден ICOM — вход, управление, механизм и выход
теми же именами, что в документе.

Полная сверка — через декомпиляцию:

```bash
./ramusc decompile /tmp/skirt.rsf > /tmp/back.yaml
diff <(./ramusc decompile /tmp/skirt.rsf --json) \
     <(./ramusc decompile /tmp/skirt.rsf --json)   # пусто: вывод устойчив
```

**Ожидается**: в `/tmp/back.yaml` у каждой работы те же потоки теми же
сторонами, что и в `examples/skirt.yaml`. Геометрия будет отличаться — она
вычислена, а не взята из документа, и это не расхождение.

## 3. Стрелки приходят на свои стороны (FR-003, SC-003)

```bash
./ramusc decompile /tmp/skirt.rsf | head -60
```

**Ожидается**: `Ткань` у «Раскроя материала» стоит во `in`, `Правила
изготовления` — в `control`, `Швея-закройщица` — в `mechanism`, `Детали
изделия` — в `out`. Перепутанная сторона здесь видна сразу.

## 4. Детерминированность (FR-011, SC-005)

```bash
./ramusc ../examples/skirt.yaml -o /tmp/a.rsf
./ramusc ../examples/skirt.yaml -o /tmp/b.rsf
cmp /tmp/a.rsf /tmp/b.rsf && echo "байт в байт"
```

## 5. Документ без связей не изменился (FR-014, SC-006)

Модель без единого потока обязана дать файл, совпадающий с собранным до этой
фичи. Проверяется тестом; руками — сборкой той же модели старым и новым
бинарём и `cmp`.

## 6. Ручная поправка сильнее (FR-009, SC-008)

Дописать одной стрелке геометрию в `layout.arrows`, пересобрать и
декомпилировать: изменившейся обязана оказаться ровно она.

## 7. Глазами в Ramus — то, чего не проверит ни один тест

Единственный способ убедиться, что файл не просто читается нами, а является
моделью для Ramus. Делается дважды: на ступени 3 (A-0, пять стрелок) и в конце.

Открыть `/tmp/skirt.rsf` в Ramus и проверить:

1. файл открывается без сообщения об ошибке;
2. на контекстной диаграмме A-0 видна одна работа, к ней приходят стрелки с
   четырёх сторон и каждая подписана;
3. подписи стоят на месте и не обрезаны — это проверка оценки ширины рамки (В11);
4. на A0 стрелки идут между блоками, а не сквозь них;
5. граничная стрелка A0 продолжает стрелку A-0: Ramus показывает её как одну и
   ту же, а не как две разные и не в скобках туннеля — это проверка общего
   кросспоинта (В5);
6. перетащить блок мышью: стрелки обязаны остаться присоединёнными;
7. сохранить из Ramus и открыть снова — файл не должен испортиться.

Пункты 3 и 5 проверяют ровно те два места, где мера не полна; если что-то
пойдёт не так, пойдёт именно там.

## 8. Что смотреть при расхождении

```bash
./ramusc dump /tmp/skirt.rsf > /tmp/mine.txt
python3 ../algodemo/rsf.py /tmp/skirt.rsf > /tmp/ref.txt
diff /tmp/mine.txt /tmp/ref.txt
```

`algodemo/rsf.py` проверен round-trip-тестом на реальных файлах: при расхождении
сначала выясняется, кто прав, и только потом правится код.
