# Контракт: разведение по каналам

## 1. Внешние интерфейсы не меняются

| Поверхность | Изменение |
|---|---|
| CLI `ramusc` (команды, флаги, коды возврата) | нет |
| Формат `--json` диагностики, коды `internal/diag` | нет |
| Входной язык, `model.schema.json` | нет |
| IR (`internal/ir`) | нет |
| Формат `.rsf`: таблицы, колонки, последовательности | нет |
| Публичная функция `layout.Apply(m *ir.Model)` | подпись та же |

Меняются **значения** координат в `layout.arrows[].segments[].points` у моделей,
где было наложение. Число стрелок, сегментов и точек не меняется ни на одной
модели.

Новых диагностик фича не вводит. Наложение, которое не удалось развести
(FR-010), — не ошибка входа: документ верен, места на листе нет. Сообщать о нём
кодом означало бы уронить компиляцию там, где Ramus нарисует пусть тесную, но
рабочую диаграмму.

## 2. `internal/layout` — новый неэкспортируемый проход

```go
// channels разводит сегменты разных стрелок, попавшие на одну линию.
//
// Работает по готовым ломаным: маршруты уже построены route() и tree(), и
// здесь меняются только координаты. Форма ломаной, число точек и привязка
// концов к блокам сохраняются.
//
// occupied — линии, которые заняты не нами: сегменты, написанные автором
// (Р2), их раскладка не двигает, но и не игнорирует.
func channels(all []*arrow, blocks map[string][]box, occupied []claim)
```

Вызывается из `placeArrows` один раз, после `branch()` и после того, как у всех
стрелок заполнено `points`.

### Изменение порядка в `placeArrows`

Сегодня ломаная считается лениво, в `segmentOf`. Разведению нужны все
координаты сразу, поэтому порядок становится таким:

```
arrows()      → стрелки диаграмм
branch()      → деревья вместо параллельных линий
materialize() → у каждой стрелки заполнено points        ← выделяется из segmentOf
channels()    → координаты разведены                     ← новое
segmentOf()   → запись в ir.Layout, ломаная уже готова
```

`route()` и `tree()` не меняются. `segmentOf` перестаёт строить маршрут и только
переносит готовый.

## 3. Инвариант, который проверяется тестом

Главный контракт фичи — не подпись, а свойство модели после `layout.Apply`.

```go
// TestNoSegmentOverlap — сегменты разных стрелок не накладываются.
//
// Наложение: два отрезка одной ориентации на одной координате, чья общая часть
// имеет ненулевую длину. Пересечение в точке допустимо и не проверяется.
func TestNoSegmentOverlap(t *testing.T)
```

Правила проверки:

1. Единица сравнения — пара сегментов **разных** стрелок на **одной**
   диаграмме. Стрелка — пара «поток + диаграмма».
2. Сегменты одной стрелки пропускаются: общая магистраль намеренна (FR-003).
3. Сегменты, написанные автором, пропускаются в роли «виноватого», но
   учитываются в роли «пострадавшего»: двигаться обязана автоматическая
   стрелка (FR-009).
4. Сравнение координат точное. Совпадения рождаются из одной формулы,
   применённой дважды, и совпадают побитово (research.md, решение 8).
5. Диагональных сегментов нет: маршруты строятся из горизонталей и вертикалей.
   Сегмент, не являющийся ни тем, ни другим, — сам по себе ошибка, и тест
   обязан об этом сказать, а не молча его пропустить.

Проверка идёт по всему набору `documents()` из `arrow_test.go` плюс новые
фикстуры. Новый документ добавляется в перечень — код теста не трогается.

## 4. Сопутствующие инварианты, которые обязаны уцелеть

Уже проверяются существующими тестами; фича не вправе их сломать.

| Инвариант | Где сторожится |
|---|---|
| Узел ветвления — одна точка | `layout`: `TestCrosspointIsOnePoint` |
| Точки одной прямой внутри сектора делят номер линии | `generate`: `TestOrdinatesSharedWithinSector` |
| Каждая связь нарисована | `layout`: `TestEveryLinkDrawn` |
| Сегменты правильной формы, концы — блок, край или узел | `layout`: `TestSegmentsAreWellFormed` |
| Авторская геометрия не тронута | `layout`: `override_test.go` |
| Круг «документ → файл → документ» замкнут | `generate`, `decompile` |
| Две сборки дают побайтово одинаковый файл | принцип III; `generate` |

## 5. Новая проверка детерминированности

```go
// TestChannelsAreStable — разведение зависит только от текста документа.
//
// Модель раскладывается дважды из одного и того же файла; координаты обязаны
// совпасть побитово. Обход отображения, попавший в раздачу каналов, всплывёт
// здесь, а не в чужом диффе через три месяца.
func TestChannelsAreStable(t *testing.T)
```

## 6. Эталоны

Эталоны `testdata/golden/` сняты с `examples/ИзготовлениеЮбки.rsf` — файла,
написанного самим Ramus и нами только читаемого. Разведение на них не влияет,
и `make golden` этой фиче не нужен. Если эталон всё же поехал — значит проход
тронул то, чего трогать не должен, и это повод разбираться, а не переписывать
эталон.
