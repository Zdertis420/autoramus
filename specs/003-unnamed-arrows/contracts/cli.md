# Phase 1. Контракт CLI

Меняется одна команда — `ramusc decompile`. Форма вывода и коды возврата уже
определены; фича добавляет к ним один вид причины отказа.

---

## `ramusc decompile <file.rsf>`

### Исходы

| Условие | stdout | stderr | Код |
|---|---|---|---|
| Файл выражается языком, потерь нет | документ | пусто | 0 |
| Файл выражается языком, есть потери | документ | сводка потерь | 0 |
| **Файл содержит стрелку без имени** | **пусто** | **перечень причин отказа** | **2** |
| Файл содержит работу без имени, дубль имени, колонку неизвестного типа | пусто | перечень причин отказа | 2 |
| Файл не читается | пусто | сообщение об ошибке | 1 |

Строка «пусто» в stdout означает буквально ноль байт: при `-o файл` файл не
создаётся и существующий не перезаписывается.

### Форма отказа

Формат не новый — к нему добавляются строки нового вида:

```
<файл>: файл не выражается входным языком полностью
  <причина>
  <причина>
ничего не записано
```

Строка причины для безымянной стрелки:

```
  стрелок без имени: 1 («под работа 1» (выход) → «под работа 2» (вход))
```

Правила текста — П-4 в [data-model.md](../data-model.md). Одна строка на одну
стрелку: у `тест.rsf` строк три, у `ФормированиеТП.rsf` — одна.

### Гарантии

* **Все причины сразу.** Безымянные стрелки печатаются вместе с прочими
  находками, а не вместо них. Автор, у которого в файле и работа без имени, и
  безымянная стрелка, узнаёт об обеих за один запуск.
* **Детерминированность.** Один и тот же файл даёт побайтово один и тот же
  перечень причин в том же порядке (П-3).
* **Ничего не записано.** Ни при каких условиях отказ не сопровождается частичным
  документом.

```
  стрелок без имени: 1 («под работа 2» (выход) → «под работа 3» (вход))
  стрелок без имени: 1 («под работа 3» (выход) → «под работа 4» (вход))

```

Код 2, stdout пуст.

### `examples/ФормированиеТП.rsf`

```
examples/ФормированиеТП.rsf: файл не выражается входным языком полностью
  стрелок без имени: 1 («Оформление, нормконтроль и утверждение пояснительной записки» (выход) → «Разработка описания основных технических решений» (вход), «Разработка по подготовке объекта автоматизации к вводу системы в действие» (вход))
ничего не записано
```

Код 2, stdout пуст. Одна стрелка с ветвлением на два приёмника — не две и не
шесть.

### `examples/ИзготовлениеЮбки.rsf`

Не меняется: документ на stdout, пустой stderr, код 0. Эталоны
`izgotovlenie-yubki.{yaml,json}` и `izgotovlenie-yubki.dump.txt` остаются
побайтово прежними — это контрольный случай.

### `ramusc/testdata/testModel.rsf`

Отказ был и остаётся, но причин стало две. Измерено при реализации: в файле
двенадцать секторов без потока, то есть четыре безымянные стрелки, и все они —
между работами, у которых тоже нет имени.

```
testdata/testModel.rsf: файл не выражается входным языком полностью
  работ без имени: 4
  стрелок без имени: 1 («работа без имени» (выход) → «работа без имени» (вход))
  стрелок без имени: 1 («работа без имени» (выход) → «работа без имени» (вход))
  стрелок без имени: 1 («работа без имени» (выход) → «работа без имени» (вход))
  стрелок без имени: 1 («работа без имени» (выход) → «работа без имени» (вход))
ничего не записано
```

Подстановка «работа без имени» вместо пустых кавычек — решение по ходу
реализации: `«» (выход) → «» (вход)` читалось бы как опечатка, а не как
положение дел. Что делать, автору говорит первая строка: назвать работы.

## Чего контракт не касается

* `ramusc validate` — во входном языке безымянной стрелки не существует,
  проверять нечего;
* `ramusc dump` — показывает содержимое файла как есть, включая секторы без
  потока; отказ к нему не относится;
* `--json` у `decompile` — влияет на формат документа, а не на форму отказа;
  при отказе документа нет ни в каком формате;
* коды `internal/diag` — не заводятся и не переименовываются.
