# Как убедиться, что стрелки стали верными

Главная проверка этой фичи — глазами в Ramus, и она же первая: пока неизвестно,
одна причина у пропажи или две, остальное делать вслепую.

## 0. Разделяющий опыт — до всякого кода

Собрать два файла и открыть оба в Ramus.

```bash
cd ramusc
make build
./ramusc ../examples/skirt.yaml -o /tmp/skirt.rsf
./ramusc decompile ../examples/ИзготовлениеЮбки.rsf -o /tmp/yubka.yaml
./ramusc /tmp/yubka.yaml -o /tmp/yubka.rsf
```

Разница между ними измерена: в `skirt.rsf` два номера узла стоят у трёх точек
одной диаграммы каждый, в `yubka.rsf` таких нарушений ноль.

| Что видно в Ramus | Вывод |
|---|---|
| в «Юбке» граничные стрелки есть, в `skirt` нет | причина одна — противоречивый узел; чинит её ветвление |
| в обеих не видно | причин две; вторую искать дальше, первый подозреваемый — `attribute_decomposition_types` |
| видно в обеих | пропажа зависит не от файла, а от того, как он открыт; выяснить, чем отличались условия |

Результат записать в `research.md`, В8. Это не формальность: от него зависит
объём работ.

## 1. Инвариант узла (FR-004, FR-005, SC-003)

```bash
go test ./internal/generate -run Junction
```

**Ожидается**: ни один номер узла не стоит у двух разных точек одной диаграммы.
До ветвления эта проверка обязана падать на `skirt.yaml` — она и воспроизводит
дефект.

## 2. Один вход на диаграмму (FR-002, FR-003, SC-002)

```bash
./ramusc dump /tmp/skirt.rsf | grep 'Правила изготовления'
```

**Ожидается**: на диаграмме A0 ровно один сектор этого потока начинается на краю
листа; остальные начинаются в узлах. Сейчас с края начинаются три.

## 3. Ветвление узнаётся (FR-004)

```bash
go test ./internal/layout -run Tree -v
```

**Ожидается**: рисунок совпадает с `тест.rsf` по строению — вход, магистраль,
цепочка узлов, отводы; у каждого узла ровно одна точка.

## 4. Ординаты (SC-004)

```bash
go test ./internal/generate -run Ordinate
```

**Ожидается**: у стрелки с ветвлением появились общие ординаты (сегменты на
общей линии делят номер), и ни под одним номером не лежит двух координат.

## 5. Полосы (FR-007, SC-004)

```bash
go test ./internal/layout -run Lane
```

**Ожидается**: два потока, идущие между одной парой блоков, лежат на разных
координатах; два прогона дают одно и то же распределение.

## 6. Ничего не сломалось (FR-010, SC-005, SC-006)

```bash
make check
./ramusc ../examples/skirt.yaml -o /tmp/a.rsf
./ramusc ../examples/skirt.yaml -o /tmp/b.rsf
cmp /tmp/a.rsf /tmp/b.rsf && echo "байт в байт"
```

**Ожидается**: все тесты зелены, связи не потеряны, файл детерминирован.

## 7. Глазами в Ramus — итоговая проверка

Открыть `/tmp/skirt.rsf`:

1. на A0 видна каждая стрелка документа — ни одной пропавшей (SC-001);
2. «Правила изготовления» входят на лист одной линией и расходятся к трём
   работам (SC-002);
3. подпись потока стоит один раз, а не у каждой ветви;
4. соседние стрелки различимы, не слиты в одну линию (SC-004);
5. перетащить блок мышью — стрелки следуют за ним (SC-008);
6. сохранить из Ramus и открыть снова — файл не испортился.

Пункты 1 и 2 — то, с чего фича началась. Если после всех правок пункт 1 не
выполняется, работа не закончена, сколько бы тестов ни было зелено.
