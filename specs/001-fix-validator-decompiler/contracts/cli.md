# Phase 1. Контракт командной строки

Внешний интерфейс `ramusc` — команды, потоки и коды возврата. Ниже только то, что
эта работа меняет или впервые фиксирует. Остальное описано в `CLAUDE.md` и не
трогается.

## Затрагиваемые команды

| Команда | Меняется |
|---|---|
| `ramusc decompile <file.rsf>` | появляется отказ по непереносимому содержимому; в выводе появляется секция классификаторов |
| `ramusc dump <file.rsf>` | не меняется — инструмент сверки, показывает файл как есть, включая то, что языком не выражается |
| `ramusc validate <file>` | не меняется по поведению; расширяется покрытие видов диагностики |

## `decompile`: коды возврата

| Код | Когда | Поток вывода | Поток ошибок |
|---|---|---|---|
| 0 | файл переносится целиком | документ | пусто |
| 2 | найдено непереносимое содержимое | **пусто** | перечень находок |
| 2 | файл не читается, не `.rsf`, неверный вызов | пусто | причина |

Кода 1 у `decompile` нет и не появляется: `1` означает «вход невалиден» для
документов модели, а `.rsf` с непереносимым содержимым не является невалидным —
он просто выражается не полностью.

**Инвариант.** При коде 2 в поток вывода не попадает ни одного байта. Решение об
отказе принимается до начала печати. Проверяется тестом: при отказе с `-o` файл
не создаётся и не перезаписывается.

## `decompile`: сообщение об отказе

Идёт в поток ошибок. Строится из перечня находок, а не склеивается по случаю:
FR-003 требует называть вид, количество и, где применимо, элемент; FR-004 требует
перечислить все виды сразу.

Форма — по одной строке на вид находки, с указанием количества:

```
ошибка: файл не выражается входным языком полностью
  работ без имени: 8
  колонок неизвестного типа: 1 (справочник «каталог 3», колонка «дата»)
ничего не записано
```

Последняя строка обязательна: автор должен понимать, что частичного результата не
осталось ни в выводе, ни в файле по `-o`.

**Не является диагностикой документа.** Это сбой команды, а не разбор модели,
поэтому находки не проходят через `internal/diag`, не получают кодов из закрытого
списка и не появляются в `--json`. Так же ведёт себя `dump` на нечитаемом файле.

## `decompile`: секция классификаторов в выводе

Печатается после работ и потоков, перед `layout`. Отсутствует целиком, если
классификаторов нет, — пустая секция не печатается (edge case спецификации).

Порядок детерминирован: классификаторы по возрастанию идентификатора, колонки по
позиции и идентификатору, строки по идентификатору. Две декомпиляции одного файла
дают одинаковые байты.

Системные квалификаторы Ramus и квалификатор самой диаграммы в секцию не попадают.
В `testModel.rsf` это означает пять справочников из девятнадцати квалификаторов.

## Контракт «вывод проходит проверку языка»

Для любой модели, декомпилированной с кодом 0, справедливо:

```
ramusc decompile M.rsf -o out.yaml && ramusc validate out.yaml
```

завершается кодом 0 либо 0 с предупреждениями. Ошибок — ноль.

Это уже заявленный контракт проекта; работа приводит его в исполнение на всех
моделях набора, а не на одной. Модели, получающие отказ, под контракт не подпадают
по определению — вывода у них нет.

## Обратная совместимость

`ИзготовлениеЮбки.rsf` продолжает декомпилироваться с кодом 0. Вывод не меняется:
классификаторов в файле нет, имена работ уникальны, поэтому смена адресации на
идентичность формы вывода не задевает. Эталоны `izgotovlenie-yubki.yaml`,
`izgotovlenie-yubki.json` и `izgotovlenie-yubki.dump.txt` остаются прежними.

Сдвиг любого из этих эталонов — сигнал о скрытом дефекте и разбирается до правки
эталона, а не переписывается через `make golden`.
