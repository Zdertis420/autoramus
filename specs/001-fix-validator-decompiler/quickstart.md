# Phase 1. Проверка результата

Как убедиться, что работа сделана. Все команды — из `ramusc/`, если не указано
иное. Каждый сценарий проверяет требование спецификации и в конце ссылается на
него.

## Подготовка

```bash
cd ramusc
go build -o ramusc ./cmd/ramusc
```

Проверочные модели: `../examples/ИзготовлениеЮбки.rsf` (переносится целиком) и
`testdata/testModel.rsf` (обязан получить отказ).

## Сценарий 1. Отказ вместо молчаливой потери

```bash
./ramusc decompile testdata/testModel.rsf; echo "код: $?"
```

Ожидается: код 2, поток вывода пуст, в потоке ошибок перечень находок с числом
безымянных работ (их четыре). Сегодня — код 0 и документ без классификаторов.

Отдельно проверяется, что при отказе ничего не записывается:

```bash
rm -f /tmp/out.yaml
./ramusc decompile testdata/testModel.rsf -o /tmp/out.yaml; echo "код: $?"
test ! -e /tmp/out.yaml && echo "файл не создан — верно"
```

Требования: FR-001, FR-003, FR-004, FR-016.

## Сценарий 2. Классификаторы находятся

Сквозной проверки на настоящем файле нет: `testModel.rsf` попадает под отказ.
Обнаружение проверяется на уровне разбора.

```bash
go test ./internal/rsf -run Classifier -v
```

Ожидается: пять классификаторов «каталог 1»…«каталог 5», тринадцать системных
квалификаторов и квалификатор работ отброшены, у каждого справочника одна
непустая колонка `Name` и ноль строк.

Чтение колонок пользовательских типов, строк и значений проверяется на собранных
вручную таблицах:

```bash
go test ./internal/rsf -run ClassifierValues -v
```

Требования: FR-017. Ограничение: настоящим файлом Ramus эта часть не подтверждена
(см. `research.md`, Р-4).

## Сценарий 3. Вывод декомпилятора принимается языком

```bash
go test ./internal/decompile -run OutputPasses -v
```

Ожидается: проверка идёт по перечню моделей; для моделей без отказа — ноль ошибок
валидации. Сегодня на второй модели их девятнадцать.

Вручную, на первой модели:

```bash
./ramusc decompile ../examples/ИзготовлениеЮбки.rsf -o /tmp/skirt.yaml
./ramusc validate /tmp/skirt.yaml; echo "код: $?"
```

Ожидается: код 0, три предупреждения `unused_flow` — это верное поведение, в файле
действительно есть потоки без стрелок.

Требования: FR-011, FR-012.

## Сценарий 4. Списки ICOM без повторов

```bash
go test ./internal/decompile -run ICOM -v
```

Ожидается: ни в одной работе поток не назван дважды на одной стороне. Сегодня на
второй модели семь повторов — следствие того, что работы адресуются по имени, а у
четырёх из них имени нет.

Требования: FR-013.

## Сценарий 5. Обе модели участвуют в проверках

```bash
go test ./internal/rsf -run 'RoundTrip|Model' -v 2>&1 | grep -c testModel
```

Ожидается: значение больше нуля — вторая модель действительно задействована.
Сегодня ноль: имя файла зашито константой и указывает только на первую модель.

Round-trip обеих моделей побайтовый:

```bash
go test ./internal/rsf -run RoundTrip -v
```

Требования: FR-009, FR-010.

## Сценарий 6. Каждый вид диагностики покрыт

```bash
go test ./internal/diag -run Coverage -v
```

Ожидается: список непокрытых видов пуст. Сегодня их девятнадцать, среди них
`no_root`, `multiple_roots`, `flow_not_produced`, `schema_enum`, `schema_const`.

Проверка самой проверки: добавить в `internal/diag/code.go` фиктивный вид и
убедиться, что тест падает и называет его. После проверки — откатить.

Требования: FR-006, FR-007, FR-008.

## Сценарий 7. Приёмка целиком

```bash
make check
```

Ожидается: зелёно. Эталоны первой модели не изменились:

```bash
git diff --stat testdata/golden/izgotovlenie-yubki.*
```

Ожидается: пусто. Непустой вывод означает, что смена адресации задела форму вывода
там, где не должна была, — это разбирается, а не переписывается через `make golden`.

Требования: FR-005, FR-018.

## Что этими сценариями не проверяется

- Перевод элементов DFD во входной язык: внешней ссылки, хранилища и роли нет ни в
  одной из двух моделей (FR-019, отложено).
- Чтение непустых справочников на файле, записанном самим Ramus.

Обе дыры закрываются одной третьей моделью из Ramus: со справочником на пару
колонок и несколько строк и с тремя видами элементов DFD.
