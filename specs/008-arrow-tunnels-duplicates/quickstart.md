# Как проверить, что починилось

Три части фичи проверяются по отдельности и в любом порядке. Ни одна проверка не
требует запускать Ramus — кроме последней, и она названа отдельно.

## Подготовка

```bash
cd ramusc && make build
```

Скрипт разведки лежит в спецификации и работает по любому `.rsf` без сборки:

```bash
python3 specs/008-arrow-tunnels-duplicates/evidence/tunnels.py examples/тест.rsf
```

Он считает правило Ramus по таблицам файла (`contracts/crosspoints.md`, §2) и до
появления `ramusc dump`-раздела служит той же цели. После — оба должны давать
один ответ; расхождение означает, что правило записано по-разному в двух местах.

## Часть 1 — оверрайд не съедает стрелку

**Было**: три сегмента, описанные автором для A0, стирали сегмент на A-0 и ветку
к третьей работе. `validate` молчал.

```bash
./ramusc/ramusc examples/skirt-full.yaml -o /tmp/skirt-full.rsf
./ramusc/ramusc dump /tmp/skirt-full.rsf | grep 'Правила изготовления'
```

**Ожидается**: сегмент на диаграмме `'3'` (это A-0) присутствует, и сегменты на
A0 доходят до всех трёх работ, которые объявили это управление:

```
диаграмма='3'                    поток='Правила изготовления'  край диаграммы(3) -> Изготовление юбки:управление(T)
диаграмма='Изготовление юбки'    поток='Правила изготовления'  край диаграммы(3) -> узел#…
...
```

**Отдельно — что оверрайд остался оверрайдом**: координаты, заданные автором,
не изменились. Сегмент `[[300, 40], [300, 80]]` из `skirt-full.yaml` доезжает до
файла как есть.

**Обратная сторона** — непокрытая связь теперь названа:

```bash
./ramusc/ramusc validate ramusc/testdata/models/partial-arrow-layout.yaml
```

**Ожидается**: `incomplete_arrow_layout` с позицией стрелки в `layout.arrows` и
именем работы, до которой сегменты не дошли. Код возврата 1.

## Часть 2 — дубль схлопывается

```bash
./ramusc/ramusc validate specs/008-arrow-tunnels-duplicates/evidence/duplicate-link.yaml
./ramusc/ramusc specs/008-arrow-tunnels-duplicates/evidence/duplicate-link.yaml -o /tmp/dup.rsf
./ramusc/ramusc dump /tmp/dup.rsf | grep 'Заготовка'
```

**Ожидается**:

- `validate` даёт одно предупреждение `duplicate_link` с позицией записи в
  `links`, код возврата 0;
- в `dump` ровно одна строка `Первая:выход(R) -> Вторая:вход(L)`, а не две.

**Было**: две строки, ни одного сообщения, у обоих секторов общие кросспоинты
`14` и `15`.

**Проверить заодно**, что место на стороне блока пересчиталось: вход «Второй» —
единственный, и стрелка должна прийти в середину стороны, а не в треть.

## Часть 3 — туннели только там, где просили

### 3.1 Инвариант по всему набору

```bash
cd ramusc && go test ./internal/rsf/ -run Tunnel -v
```

**Ожидается**: на файлах, записанных самим Ramus, столько туннелей, сколько
измерено (`contracts/crosspoints.md`, §3): ноль в `тест.rsf`,
`ИзготовлениеЮбки.rsf` и `testModel.rsf`, один в `ФормированиеТП.rsf`. На наших
документах — ноль, кроме тех, где автор написал `tunnel`.

Ноль на файлах Ramus — это проверка самого правила. Если там появятся скобки,
неверно выведено правило, а не собран файл.

### 3.2 Явный туннель у DFD

```bash
./ramusc/ramusc validate ramusc/testdata/documents/dfd-tunnel.yaml
./ramusc/ramusc ramusc/testdata/documents/dfd-tunnel.yaml -o /tmp/dfd.rsf
./ramusc/ramusc dump /tmp/dfd.rsf | sed -n '/ТУННЕЛИ/,$p'
```

**Ожидается**: проверка молчит, а в разделе `ТУННЕЛИ` ровно те концы, потоки
которых названы в `tunnel` работы.

Убрать `tunnel` из документа — и та же проверка обязана дать
`flow_not_decomposed` на каждый убранный поток. Это и есть разница между
«я так задумал» и «я забыл дописать декомпозицию».

### 3.3 Круг остаётся замкнут

```bash
cd ramusc && go test ./internal/decompile/ ./internal/generate/
```

Декомпилятор — исполняемая спецификация генератора: всё, что он вычитывает,
генератор обязан записать. Новое поле `tunnel` у работы должно пережить круг
«документ → файл → документ» без потерь.

## Полная проверка перед коммитом

```bash
cd ramusc && make check
```

Эталоны переписываются осознанно и попадают в дифф вместе с кодом:

```bash
cd ramusc && make golden
```

Ожидаемый дифф эталонов: две новые модели с диагностикой, плюс в выводе `dump`
на `examples/ИзготовлениеЮбки.rsf` — добавленный раздел `ТУННЕЛИ` со строкой
`туннелей нет`. Всё прочее в эталонах меняться не должно; изменение в разделах
`РАБОТЫ`, `ПОТОКИ` или `СЕКТОРЫ` означает, что задет вывод, который сверяется с
`algodemo/rsf.py`.

## Чем фича не закрывается

Ни одна проверка выше не запускает Ramus. Правило туннелей выведено из
исходников и подтверждено на четырёх файлах, записанных самим Ramus, — но это
вычисление по таблицам, а не картинка.

**Перед тем как считать фичу сделанной**, откройте в Ramus собранный
`examples/skirt-full.yaml` и посмотрите глазами:

1. на A0 у «Правил изготовления» один вход с верхнего края и ветки ко всем трём
   работам;
2. на A-0 это управление есть;
3. скобки стоят только у «Регламента приёма» и «Менеджера» на «Приёме заказа» —
   там, где автор написал `tunnel`;
4. ни одна стрелка не двоится.
