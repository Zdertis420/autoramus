# Контракт: стрелка не идёт сквозь блок

## 1. Внешние интерфейсы

| Поверхность | Изменение |
|---|---|
| CLI `ramusc`: команды, флаги, коды возврата | нет |
| `--json` диагностики | **новый код** `arrow_through_block`, уровень `warning` |
| коды `internal/diag` | добавлен `CodeArrowThroughBlock`; прежние не меняются |
| Входной язык, `model.schema.json` | нет |
| IR (`internal/ir`) | нет |
| `layout.Apply(m *ir.Model)` | подпись та же |
| `validate.Source`, `validate.Build` | подписи те же; последней ступенью — раскладка и проверка геометрии |
| `internal/generate` | не трогается |

### Диагностика

```go
// Геометрия. Выдаётся после раскладки: блок, сквозь который идёт стрелка,
// может быть расставлен раскладкой.
const (
	// CodeArrowThroughBlock — отрезок стрелки, точки которой задал автор,
	// проходит сквозь блок своей диаграммы. Предупреждение: авторское не
	// правится (Р2), но и молча не пропускается.
	CodeArrowThroughBlock Code = "arrow_through_block"
)
```

Пример (модель `testdata/models/arrow-through-block.yaml`; числа условные):

```json
{
  "severity": "warning",
  "code": "arrow_through_block",
  "message": "стрелка «указание» на диаграмме «Проба» проходит сквозь работу «Середина»",
  "path": "/layout/arrows/0/segments/0/points/1",
  "line": 31,
  "column": 22
}
```

Код возврата при одних предупреждениях — 0, файл собирается (FR-011).

## 2. Конвейер

```
разбор → схема → IR → смысл → [нет ошибок] → раскладка → геометрия
```

* Раскладка вызывается внутри `validate.Build`, только если ошибок нет
  (лесенка). Авторские сегменты запоминаются до неё.
* Проверка геометрии выдаёт только предупреждения.
* `ramusc validate` и `ramusc <file>` получают один и тот же список
  диагностики.
* Повторный `layout.Apply` на разложенной модели ничего не меняет
  (идемпотентность, research И4) — сторожит тест.

## 3. Обход

Для каждой стрелки, которую прокладывает раскладка, — первый чистый из
кандидатов (data-model «Кандидат маршрута»): прежний шаблон, полоса из
`lanes()`, коридор над, коридор под. «Чистый» — ни один отрезок не проходит
внутри блока диаграммы (строгие неравенства, как `crosses` в `route.go`).

Применяется в: `forward` (вход, управление, механизм), выход к правому краю,
ветки дерева от края листа (`tree`). `feedback` и `fromBorder` уже перебирают
полосы; им добавляется коридорный запасной вариант, если перебор не нашёл
чистой.

## 4. Авто-блоки и авторские

`Apply`: после расчёта лестницы авто-блок, налезающий на авторский или уже
сдвинутый авто-блок той же диаграммы, сдвигается вправо за помеху на
`blockClearance = 24`; за листом — вниз; и так за листом — остаётся на
ступени (названная граница). Авто-блок без помех не двигается.

## 6. Эталоны

Новый: `testdata/golden/arrow-through-block.diag.json` — `make golden`
осознанно. Прочие эталоны не меняются: модели с ошибками до раскладки не
доходят, а те, что дают одни предупреждения (`duplicate_link`), доходят, но
авторских стрелок не несут — предупреждению неоткуда взяться. Проверяется
тем, что `git diff testdata/golden/` после фичи показывает один новый файл и
ни одного изменённого.

Декомпилированная модель несёт всю геометрию как авторскую: если в файле
Ramus стрелка идёт сквозь блок (в `ФормированиеТП.rsf` такая одна), её
декомпиляция получит предупреждение — и это верно.
